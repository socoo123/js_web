## 1. 学员的唯一主线

读本课任务 → 在自己的 `inventory/` 修改 → 看页面/输出 → 复现并修复一个错误 → 检查 → 在 `notes/next.md` 留下一步。每天两课，Lab 收尾就是对应课程的练习，不再额外布置一套大作业。

学员通常一直使用同一工作目录。若前一阶段未完成，可把固定起点恢复到**新目录**后继续当前 Lab；概念前置仍要读。恢复获得的是前置能力，不能已经包含当前 Lab 待实现的答案。

## 2. 每个 Lab 的具体任务

### L1：让库存规则可靠（C01–C10）

- **已有**：C00 可启动的 P001 单商品卡片、固定数据和工具入口。
- **推进**：C01–C03 环境/页面/输入边界；C04–C07 统计、草稿、函数和 this；C08–C10 数据查询、集合、撤销/树。
- **交付**：在同一 `src/core/inventory.js` 中形成可调用的规则。语言练习服务于理解 JS，不提前引入 React 或复杂分层。
- **收尾场景**：初始 6/52/2634800；P001 输入“3”得到 15，撤销回 12；0 合法，空白/负数/小数/“3件”拒绝；取消草稿不改原 tags；排序不改原顺序。
- **主要证据**：Console/Sources 的类型、作用域、引用和 this；检查实际学员文件。沿用已发布记录，不要求重新制造全部旧故障。

### L2：做成可用的原生页面（C11–C20）

- **已有**：C10 的业务规则与卡片。
- **推进**：C11–C14 列表/异步/请求/存储；C15–C16 布局与一次明确的模块拆分；C17–C20 Node 报表、包管理与第一批 UT。
- **交付**：`src/vanilla` + `src/services` + 拆分后的 `src/core` + `src/cli/report.js`；浏览器和 Node 复用同一计算。
- **收尾场景**：筛选 P004，改库存 3→8，只改它，总库存 57；取消则仍为 3/52；刷新恢复已保存值；导入坏 JSON/字段时好数据原文保留；360/768/1280px 可用；初始 Node 报表为 6/52/2634800。
- **工具教学**：C18/C19 的锁与包管理器实验在 `.lab/sandboxes`，不改主锁；C20 UT 能抓住空白库存，TS 片段只解释类型检查与运行的边界。

### L3：React 应用从小到完整（C21–C36，阶段 A）

| 学习段 | 在当前应用增加什么 | 必须能观察到的结果 |
| --- | --- | --- |
| C21–C24 | JSX/组件、props、状态、列表身份与派生统计 | 六商品；P001 连续 +3 得 15，延迟 +3 期间立即 +1 最终 16；排序后身份不串 |
| C25–C28 | 表单、草稿归属、reducer/Context、ref | 0 可保存、空白拒绝；P001 草稿取消后开 P002 显示 0；取消定时任务后不补货；焦点正确 |
| C29–C32 | Effect 清理、详情请求、Hook/hash 路由、Query | 一次快捷键一次动作；P001 慢/P002 快最终显示 P002；P004 详情刷新/返回可用；缓存按 id 隔离 |
| C33–C36 | 异步提交/乐观反馈、性能定位、测试与排错 | 提交中防重复，失败回滚并保留草稿；库存与统计同步；RTL 校验/失败重试与静态浏览器主流程通过 |

**数据归属交接是本 Lab 的重点**：C24–C31 商品状态由 React/reducer 管理，快照只承担明确的保存/恢复；C32 起 repository 持有可写业务数据及持久化，Query 负责服务端状态缓存，组件 state 留选中项/筛选/编辑草稿。修改走统一 mutation/repository 路径，移除当前入口的旧请求 Effect 和重复可写商品副本。旧实现留在对应课快照里。

C36 完成态包括新建/编辑/删除、详情、快照恢复和失败处理。React 基础课不从最终 App 开始，Query/Action 不倒灌至 C21；参考片段组合需要的导入、组件插入和事件连接必须在正文讲清。

### L4：四种界面适配，同一业务边界（C37–C44，阶段 B）

C36 起点保留可运行的 React 主应用与公共 core。各 adapter 只在轮到本课时启动，切换用现有 CLI 选择任务并重启服务；不要求同时运行四个服务。

| 课程 / 目录 | 实作范围 | 重点错误 |
| --- | --- | --- |
| C37 / `notes/components.md` | 写出列表/编辑契约，比较可访问性、主题、维护、许可 | 按排名选库、用可见索引代替 id |
| C38 / `adapters/antd` | 表格与编辑弹窗，调用公共规则 | initialValues 残留旧草稿，排序后改错商品 |
| C39 / `notes/ui5-choice.md` | Fiori 和 UI5 家族选择；不增加独立运行任务 | 混淆 SAPUI5/OpenUI5/原生组件/React 包装 |
| C40–C42 / `adapters/openui5` | MVC/JSONModel、绑定、编辑 Fragment、i18n、详情/hash、有限 OData V2 mock | 模块路径、binding context、setProperty、取消污染、缺静态资源 |
| C43 / `adapters/web-components` | 沿用原生列表/筛选，小表单换两个组件（输入/按钮） | 布尔 attribute/property、事件值、Shadow DOM 与资源 |
| C44 / `adapters/ui5-react` | 替换列表与编辑区，调用公共规则/repository | 包装事件取值、原生 form 提交链、回车重复保存 |

**四个 adapter 共用的验收向量**（每个场景从独立固定数据开始）：

1. 筛选出 P004，选中与提交都使用 id；编辑草稿为 8 后取消，P004 仍 3，总库存 52。
2. 再次编辑并保存 8：P004=8、P001=12、总库存 57；名称/分类/价格/tags 不丢失。
3. 空白/负库存拒绝，合法 0 保存；键盘可完成打开/输入/取消/保存，错误信息可定位。
4. 清空筛选后正确显示全量数据；有限 OData 分页子集不能冒充全量统计。

原生 Web Components 的完整筛选/列表外壳可预置，学员只接输入、按钮与公共编辑行为。四个界面共享验收向量，不要求共享一套 DOM 测试脚本或各实现全量 CRUD。

OpenUI5 特有验收：P004 详情刷新、回退、未知 id；V2 metadata、读取/过滤/排序/分页请求可见；区分 JSONModel、ODataModel、V2/V4。mock 是静态浏览器教学实现，不扩展到真实 SAP 鉴权或完整 OData 写服务。

### L5：把项目交付出来（C45–C48，阶段 C）

- **已有**：C44 包中保留的 C36 React 主应用和 L4 adapters。主学习入口回到 `src/react`，不把 UI5 React 变成所有后续课程的强制基础。
- **任务**：C45 按层排错并记证据；C46 构建和严格静态路径；C47 选择 3–5 条真实风险回归；C48 不看答案增加一个已学过的筛选条件、解释实现并定位一个故障。
- **测试目标**：非法快照不破坏好数据、连续交互正确、请求失败后可恢复，必要时补表单身份/资源路径。已有有效用例计入，不为凑数量重复写。
- **交付物**：生产产物、运行/恢复说明、`notes/debug.md`、`notes/test-plan.md`、`notes/final-review.md`，沿用已有 notes 而非另建报告系统。
- **路径验收**：课程网站 `/js_web/`；库存演示默认 `/js_web/demos/inventory/`。严格服务器无 SPA fallback，直接访问、hash 刷新、静态数据/字体/i18n/模块资源正常；多个演示若上线须各占独立子路径。
- **发布边界**：站点及学习包上线必验；Lab 应用按课程说明本地构建/静态预览，不把本地成功写成在线演示已部署。实际发布演示时才核验对应线上路径。

## 3. 工作区和命令保持简单

沿用现有目录，不另搬一轮架构：

```text
labs/inventory/          学员工作区；package.json + 独立 package-lock.json
  data/                  固定输入
  src/core/              公共规则；C16 才拆模块
  src/vanilla/            原生界面
  src/react/              React 主应用
  src/services/          请求、存储、mock repository
  src/cli/               Node 报表
  adapters/              antd / openui5 / web-components / ui5-react
  tests/                 按真实风险组织的检查
  tools/                 已有 CLI 与作者提供的检查；不是学员必读框架
  notes/                 暂停、决策、故障与交付记录
  .lab/                  本地状态/隔离实验/缓存，不放权威业务源码
```

已有核心命令在工作区执行：`npm ci`、`npm run lab -- status`、`start Cnn`、`dev`、`check Cnn`、`compare Cnn`、`restore Cnn 新目录`、`report`、`build`（后七项同样接在 `npm run lab --` 后）。不要凭设计编造尚未实现的子命令；具体以 CLI/README 为准。

- `start` 只选择任务，不安装答案、不升级或改写源码；`check` 检查当前实际文件，必要时打印输入/预期/实际；`compare` 只读。
- `restore C20 ../inventory-react` 恢复的是 **C20 完成态**，作为 C21 的起点。目标非空拒绝；已有代码可继续使用，无需恢复。发行版必须已包含该快照。
- 同一发行版安装一次；沿用当前统一练习锁和已安装框架，不为本轮收尾重拆依赖。缓存/网络/机器会影响安装时间，现有实测见 [R5 记录](records/R5.md)。如跨发行版依赖有变，用新目录和该版锁重新安装。
- C18/C19 用现有 `experiment` 隔离入口；不写入网站根锁。UI5 框架首次按需下载和切服务的等待写在对应课。
- 暂停只记录当前课、已改文件、观察结果、下一件事。`.lab` 任务位置与网站 F1 主动完成标记分别管理。
