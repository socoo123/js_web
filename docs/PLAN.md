## 2. 信息架构：Lab 优先

```text
首页 Lab 标签（L1…L6） → Lab 主页 → 课程标签（C01 | C02 | …） → 打开课文 → 返回 Lab 主页该课标签
```

- **侧栏**：「开始」（工作区与 6 个 Lab、规则、按天的学习路线）→ L1–L5 各一组（组内先是「Lab 主页」，再是该 Lab 的课）→ L6 毕业挑战 → 速查手册。分组由 `astro.config.mjs` 从 `labs/catalog.json` 生成，当前页所在组展开，其余折叠。课的 URL、slug 和锚点不变；上一页/下一页按侧栏顺序走：L1 主页 → C01 … C10 → L2 主页 → …
- **首页**：Hero 下第一屏是 `HomeLabTabs`：六个 Lab 标签，面板里是目标、效果截图、「进入 Lab 主页」「从 Cxx 开始/继续」和按学习日分组的课号链接；默认选中第一个没学完的 Lab，`#lab-l3` 可深链。禁用 JS 时六个面板依次全部显示。
- **Lab 总览**（`/labs/`）：六张 Lab 卡（含 L6）、首次安装、起点与恢复。
- **学习路线**（`/roadmap/`）：由 `scripts/sync-roadmap.mjs` 生成，按 Lab 分节，每个学习日注明 4 周主线周次与 8 周路线天数，末尾接 L6。

## 3. Lab 设计

### 3.1 L1–L5 Lab 主页（统一结构）

1. **头部卡**：Lab 编号与标题、一句话目标、完成后的效果截图、课程范围、进度环、「开始/继续：下一课」按钮。
2. **课程标签**（核心）：从 catalog 生成，每课一个标签（课号、短标题、完成勾）。面板写本课要做什么（`task`）、改动文件、验收标准、主错误（触发 → 证据 → 修复）、`start/dev/check` 命令；有步骤数据的 Lab（目前 L3）在面板里显示本课步骤；面板底部是「打开课文」与上一课/下一课。WAI-ARIA tabs，方向键切换，`#c06` 深链；旧的步骤锚点（如 `#l3-c21-1`）打开对应课的标签并滚到该步。默认选中第一节未完成的课。禁用 JS 时全部面板顺序显示。
3. **收尾验收**：可勾选清单，数字沿用各 Lab 现有验收。
4. **折叠区**：起点、补课恢复、暂停、升级说明；保留 `#从哪里开始` 等已被链接的锚点。
5. 课页顶部 `LabBar` 的「返回 Lab」直接打开 Lab 主页里本课的标签。

L1–L5 的课程范围、起点、验收数字与 [labs/README.md](../labs/README.md) 的 V2 契约不变。不为 L1/L2/L4/L5 编造步骤数据；需要时逐课补写，归入 §7 的后续批次。

### 3.3 固定样例数据（不变）

权威来源为 `examples/shared/products.json`；练习数据由它派生。同一 id 的起始值一致，补货/编辑使用独立副本。

| id | name | category | stock | priceCents | tags |
| --- | --- | --- | --- | --- | --- |
| P001 | 机械键盘 | 外设 | 12 | 39900 | 热销 |
| P002 | 无线鼠标 | 外设 | 0 | 12900 | — |
| P003 | 27 英寸显示器 | 显示器 | 7 | 159900 | 新品 |
| P004 | USB-C 扩展坞 | 配件 | 3 | 29900 | 热销、新品 |
| P005 | 显示器支架 | 配件 | 25 | 19900 | — |
| P006 | 降噪耳机 | 音频 | 5 | 89900 | 热销 |

固定结果：6 种商品、总库存 **52**、总价值 **2,634,800 分**；售罄 P002；低库存只算 1–5 件，为 P004/P006（2 种、8 件、539,200 分）；分类计数 2/1/2/1；标签去重为热销、新品。新建 P007「随身转接头 / 配件 / 3 件 / 0.29 元」后为 7/55/2,634,887；P004 改为 8 件后全量总库存 57。

字段规则：id 为 `P` 加三位数字且唯一，新建自动生成；name 去首尾空格后 1–40 字；category 四选一；stock 为 0–99,999 的整数；priceCents 为非负安全整数，元输入最多两位小数；tags 为字符串数组。空白库存非法，0 合法。JSON 解析后继续校验字段；超安全整数的汇总报范围错误。

### 3.4 L5 本地后端（保留的设计，排在 §7 批次 2）

V3 §3.3 的设计继续有效：作者提供 `labs/inventory/server/`（Node 24 `node:http` + ESM，无新依赖，只监听 `127.0.0.1:8070`，`npm run lab -- api` 启动并逐行打印 `方法 路径 状态 耗时`），学员只写前端，把 C44 的 React 应用接到真实 HTTP 接口。

- 数据持久化到 `.lab/server/products.json`，先写临时文件再改名；损坏时拒绝启动并提示 reset。服务端规则只读、与参考 `src/core` 同源生成，不 import 学员可改的 `src/core`。
- 错误格式 `{"error":{"code","message","fields?","current?"}}`；默认不发 CORS 头，开发走 Vite 代理；设置 `LAB_API_CORS_ORIGIN` 才放行指定来源（C45 用它讲 CORS）。

| 方法与路径 | 作用 | 成功 | 主要失败 |
| --- | --- | --- | --- |
| `GET /api/health` | 存活检查 | 200 `{"ok":true}` | — |
| `GET /api/products` | 列表；`q`、`category`、`stock=low\|out`、`sort=id\|name\|stock\|-stock`、`page`（从 1 起）、`pageSize`（1–50，默认 20） | 200 `{items,page,pageSize,total,summary,totals}` | 400 参数非法 |
| `GET /api/products/:id` | 详情，带 `version` | 200 | 404 `NOT_FOUND` |
| `POST /api/products` | 新建，id 由服务端分配 | 201 + `Location` | 400 `BAD_JSON`；422 `VALIDATION` + `fields` |
| `PATCH /api/products/:id` | 部分修改，必须带 `If-Match: "<version>"` | 200 | 428 缺版本；409 `CONFLICT` + `current`；422；404 |
| `POST /api/products/:id/restock` | `{"quantity":3}` 补货 | 200 | 422；404 |
| `DELETE /api/products/:id` | 删除 | 204 | 404 |
| `POST /api/_lab/reset` | 恢复固定数据 | 204 | — |
| `POST /api/_lab/faults` | 让指定方法和路径接下来 N 次返回某状态或延迟 | 204 | 只在本地，供排错与测试 |

`summary` 统计筛选后的全部结果（不受分页影响），`totals` 统计全部商品。契约向量（`node --test`）：初始 6/52/2634800；`stock=low` 得 P004/P006，summary 2/8/539200、totals 不变；PATCH P004 为 8 后 totals 57；旧 version 再 PATCH 得 409 且带 current；空白库存 422 带 `fields.stock`，0 合法；新建 P007 后 7/55/2634887；DELETE 后 404；reset 回到初始值。

前端（学员写）：`src/services/api-repository.js` 保持现有 repository 方法与返回形状，另加 `listPage(params)`，HTTP 失败抛带 `status/code/fields/current` 的 `ApiError`；`src/services/data-source.js` 按 `VITE_DATA_SOURCE` 选 `api`（L5 默认）或 `mock`（Pages 演示与离线测试）；Vite 与 C46 静态预览都把 `/api` 代理到 8070。L5 目标：接上后端、全链路排错（CORS、422 字段、失效、500 后 loading、慢请求覆盖）、构建与带代理预览、3–5 条风险回归加 1 条真实后端浏览器流程、「仅低库存」走服务端；挑战为两标签页 409 冲突。网站新增 `labs/api.md` 接口文档页。Pages 不跑后端。

## 4. 界面与交互

### 4.1 一个正文栏宽度

- `--js-prose-width` 为 48rem，`--js-wide-width` 等于它。段落、代码块、`CodeCompare`、提示框、任务卡、`Effect`、图和 Lab 组件都占满这一栏，左右边缘对齐；不再有 64rem 的外扩组件，也不再在 72–90rem 收起右侧目录。
- `CodeCompare` 改为纵向：标题与共同输入 → Java 代码与输出 → 「同一件事，换成 JavaScript」→ JS 代码与输出 → 差异。长代码在块内横向滚动。
- 首页（无侧栏）画布仍为 72rem，分区组件用满画布、段落保持 48rem。
- 新组件不得自设 `max-width` 或负外边距来外扩；需要更宽的内容（宽表格、截图）在块内滚动或缩放。

### 4.2 交互看答案（渐进增强，课文正文不改）

- **旧式「先猜一猜」**（段首 `**先猜一猜：**` 加紧跟的代码块）：构建时或页面脚本标出代码里的 `// → 输出` 注释和紧跟的解释段，JS 启用时遮住它们；代码下方有「写下你的猜测」和「揭晓输出」，揭晓时逐行显示，并把猜测与真实输出并排；可重置。复制按钮仍复制完整代码。
- **`Predict` 组件**：与上面同一套视觉与交互；可选 `choices` + `answer`，点选即判。
- **练习**：「提示」「参考答案」两个 details 合成答题区：① 先自己做 → ② 看提示 → ③ 对照参考答案；答案揭晓后可选「我做对了 / 还需要再练」，结果存 `js-web-practice-v1`。
- 规则：禁用 JS 时原文完整可读；按钮有 `aria-expanded`/`aria-controls`；动画尊重 `prefers-reduced-motion`；这套增强用原生 JS，不加载 React，每页新增 JS gzip 约 10KB 以内；不改 F1 存储。

### 4.3 图：站内图形组件替代 D2

- 14 张机制图改为 `src/components/diagrams/` 下的 Astro 组件：HTML/CSS 布局，必要时用少量内联 SVG 画连线，颜色、字体、圆角全部来自 `tokens.css`，亮暗主题即时切换，360px 不出现横向滚动。
- 过程图（事件循环、状态快照、Effect 生命周期、作用域与原型链查找、DFS/BFS、输入边界、页面加载、静态交付等）提供上一步/下一步/重播，当前步骤高亮，图下 `aria-live` 说明随步骤变化。禁用 JS 时显示完整静态图。
- 图里的文字是真实 HTML 文本；`<figure>` 带说明，保留原 alt 的含义。教学内容（节点、关系、顺序、数值）与原 D2 图一致。
- D2 源码、`scripts/*-diagrams.sh`、`.d2-version` 与 SVG 产物删除（历史在 Git）；`check-build` 改为检查 14 课的构建页面都含对应 `data-diagram`。新增图沿用同一组件库，每课至多 1 张（C12、C29 可 2 张）。

### 4.4 继续有效的视觉与组件

V3 阶段 1 的视觉系统（靛蓝主色、琥珀 JS、咖啡橙 Java、12px 圆角、200ms 动效、GitHub 代码配色）、`LessonHeader`、`LabBar`、`Predict`、`Effect`、`RunSnippet`、React 演示、F1 进度 v2 与 Lab 步骤勾选继续使用。性能预算：不用 island 的页面不加载 React；单页新增 JS（gzip）不超过 80KB。

## 5. 内容边界

- **课文正文默认不改**：课号、标题、slug、URL、锚点、学习日、知识点、Java 对照主题、主错误、练习考点、验收数字与固定数据保持不变。V3 计划里「48 课按新节奏全部改写」取消；C03/C15/C23 的 V3 改写保留。
- **只做勘误**：发现知识性错误（事实、输出、版本状态、命令）时，就近修正正文与 `examples/cNN`，在 `examples/cNN/README.md` 记一行勘误与依据，STATUS 记一行摘要。拿不准的先列入勘误清单（`labs/records/V4-errata.md`），核实后再改。
- 继续有效：读者会 Java、初学前端；中文教学；HTML/CSS/浏览器不跳过；调试工具与 UT 必修；TypeScript 只做桥接与选修；Astro + Starlight + MD/MDX + 少量 React islands；npm 与根目录唯一 `package-lock.json`；Pages 子路径 `/js_web/`；Pages 只有静态文件、静态数据、浏览器内 mock 与本地存储。
- CONTENT_GUIDE 的篇幅上限与写作规则不放宽；第 16 节的呈现规则只用于新写或必须重写的段落。诚实标注照旧：页首写真实验证状态，未运行的例子就近标注。

## 6. 执行方式（更快）

### 6.1 一个窗口一批

每个窗口完成 §7 的一批，结束时已提交、推送并核验 Pages。用户提出具体修改时，以用户当次要求为准，可以插队。

### 6.2 何时并行

- 主 agent 先判断工作能否按文件归属干净拆开。能拆就同时启动 **最多 4 个**后台子 agent；拆不开就主 agent 自己做，不为凑数派发。
- 模型：用户 2026-11-07 因 Opus 额度用完，授权 **V4 批次 3 主、子 agent 均改用 GPT-6 Astra**（`openai/gpt-6-astra`）。启动子 agent 前核验在可用列表里；不可用就问用户，不静默换模型。之前批次实际使用 Opus 5.5 Extra High 的历史记录保留；工作区隔离、验收与发布要求不变。
- 隔离：每路一个 git worktree（`git worktree add -b v4-<名> ../js_web-v4/<名> HEAD`），用 `cp -cR node_modules` 克隆依赖（APFS 写时复制）。每路有明确的文件归属与禁改清单，各自用不同端口跑 `astro dev`，在自己的分支上提交，不推送、不合并 main、不再派子 agent。共享文件（`package.json`、`astro.config.mjs`、`labs/catalog.json`、`docs/`、STATUS/记录）只由主 agent 改。
- 主 agent 在子 agent 运行时并行做自己的部分，不轮询；交稿后按依赖合并分支、解决冲突、补小接线，实质问题交回原会话返修。

### 6.3 验收按改动范围

- 每批：`npm run build`（含 lint、examples、进度测试、截图新鲜度、路线同步、演示、`astro build`、`check:build`、`check:steps`）零错误；受影响页面在 360/1280px × 亮暗截图审查；涉及交互的用浏览器脚本实际点一遍（键盘、无 JS、刷新保留）。
- 改到课文或工作区代码时，再跑对应的 `npm run examples -- cNN` 与 `test:lab-*`；改到后端时跑后端契约测试。
- 只改计划或文档：检查差异、路径、引用与命令事实，不重跑浏览器全套。
