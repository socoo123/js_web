用户在 2026-10-28 提出：最近学习时间有限，逐个进入 demo 修改效率低；希望大例子贯穿、几个综合 Lab、Java/JS 代码并排，以及逐章可能错误清单。本次交付完整方案与页面审阅稿；课程改写和工具实现由后续 agent 承接。

### 保留的总约束

- 读者会 Java、初学前端；HTML/CSS、浏览器、JS 历史与标准、语言、结构、异步、Node/Bun、npm/Yarn/pnpm、详细 React、开源组件和 UI5 均保留。
- 48 课稳定 ID 与 URL、4 周主线及 8 周慢速版不变。TypeScript 只做短桥接与选修，日常代码用 JS/JSX。
- Astro + Starlight + MD/MDX 静态输出，必要时少量 React islands；仓库 `socoo123/js_web`，Pages base 为 `/js_web/`。
- 网站工程使用 npm 与唯一的根锁；独立练习工程隔离。Node/Bun 的运行时职责与包管理器职责分别讲清。
- 关键机制图只用 D2，源码构建为 SVG，总数不超过 14；不做账号、后端或在线 IDE。静态页面只用静态数据、浏览器内 mock 和本地存储。
- 保留 DevTools、React DevTools、Node inspect、Vitest/RTL、Playwright 与 Jest 的定位和练习；UI5 四个名称分清，不混用 API。
- 动态版本、安装命令、环境支持先核对官方来源；区分正式标准、Stage 4、未完成提案与实际支持，记录于 SOURCES。
- 正文面向学员；真实验证状态放页首一行，未运行的片段前标注，明细写验证 README。不把旧验证记录迁成新实现已通过。

## 3. 5 个 Lab 的业务交付

大项目暂名「库存工作台」。所有阶段处理同一组 P001–P006；产品身份、金额单位、校验和初始统计沿用 §3.1。每个 Lab 的收尾任务替代原来零散练习后的额外项目时间。

### 3.1 固定样例数据

所有课程和 Lab 统一使用这份数据。可以只取子集；同一个 id 的起始字段值必须一致，示范编辑和补货时可在此基础上更新。

| id | name | category | stock | priceCents | tags |
| --- | --- | --- | --- | --- | --- |
| P001 | 机械键盘 | 外设 | 12 | 39900 | 热销 |
| P002 | 无线鼠标 | 外设 | 0 | 12900 | — |
| P003 | 27 英寸显示器 | 显示器 | 7 | 159900 | 新品 |
| P004 | USB-C 扩展坞 | 配件 | 3 | 29900 | 热销、新品 |
| P005 | 显示器支架 | 配件 | 25 | 19900 | — |
| P006 | 降噪耳机 | 音频 | 5 | 89900 | 热销 |

各课结果必须一致的参考值：总库存 **52**；库存总价值 **2,634,800 分**（26,348.00 元）；售罄 1 个（P002）；低库存（1–5 件）2 个（P004、P006）；分类计数为外设 2、显示器 1、配件 2、音频 1；去重后的标签为热销、新品。

字段规则（原生表单、React、UI5 三个版本共用）：

- `id`：`P` 加 3 位数字，新建时自动生成。
- `name`：去掉首尾空格后为 1–40 个字符。
- `category`：外设、显示器、配件、音频四选一。
- `stock`：0–99,999 的整数。
- `priceCents`：0 或正整数。表单中按「元」输入，最多 2 位小数，保存时换算成分。
- `tags`：字符串数组，可以为空。

固定数据已保存在 `examples/shared/products.json` 和 `examples/shared/products.js`（ESM 导出）。

| Lab | 课程 | 从什么开始 | 持续增加什么 | 收尾验收 |
| --- | --- | --- | --- | --- |

## 4. 时间安排与可中断学习

4 周、24 个学习日、48 课和 72–96 小时总预算保留。学习量没有被宣传为“几个 Lab 几小时就学完”；节省的是找目录、重复搭环境、重复实现业务与追踪前置代码的时间。

| 每天两课的安排 | 时间 | 产出 |
| --- | --- | --- |
| 回看自己的上一条下一步记录 | 15 分钟 | 恢复上下文 |
| 阅读必要概念与 Java/JS 对照 | 50–70 分钟 | 两章机制与预测题 |
| 在同一工作区完成两章任务 | 80–110 分钟 | 可见的项目增量，包含原来的练习/项目时间 |
| 调试与验证 | 20–30 分钟 | 错误证据、验证结果 |
| 保存与记下下一步 | 15 分钟 | 下次打开即可继续 |

8 周路线仍是每天 1 课、每周 6 天。忙时可将一课拆为“看懂对照”“完成一次修改”“验证并记录”三次学习，不增加第三条删减必修内容的路线。

每课提供明确的暂停点，`notes/next.md` 只需记录：当前课、已改文件、当前观察结果、下一件事。课程页面的“标记完成”仍由学员主动操作；脚本通过不等于已经理解。

## 5. 一个工作区与几条固定命令

**下列目录和命令定义完整 V2 契约；已实现范围以 STATUS、catalog 的 implemented 与练习 README 为准。** 学员下载一次初始练习包或使用仓库中的 `labs/inventory/`，之后始终以该目录为工作目录。学习网站本身无需在本机启动。

```text
labs/inventory/                 # 学员长期修改的唯一工作区
  package.json                 # 独立练习工程，npm scripts 统一入口
  package-lock.json            # 练习工程自己的唯一锁文件
  data/products.json           # 由 examples/shared/products.json 生成
  src/core/inventory.js         # C01–C15 的业务入口，C16 再拆分
  src/core/                    # C16 后 validation/summary/history 等模块
  src/vanilla/                 # 原生 HTML/CSS/JS 界面
  src/react/                   # C21 起的 React 界面
  src/services/                # 请求、本地存储、浏览器内 mock
  src/cli/report.js            # C17 的 Node 报表
  adapters/antd/               # C38 的列表与表单
  adapters/openui5/webapp/     # C40–C42 的 MVC 工程
  adapters/web-components/    # C43 的原生组件
  adapters/ui5-react/          # C44 的 React 包装界面
  tests/                      # 核心、组件、浏览器验收
  notes/                      # 决策、排错、暂停点、交付记录
  .lab/                       # 本地进度与检查结果；不放业务源码
```

网站根目录继续只有一个网站用 `package-lock.json`。上面另一个锁只属于独立的练习包，沿用现有独立阶段工程的隔离原则。网站不安装 Ant Design/UI5 运行时作为全站阅读依赖；新练习工程不在每个 adapter 再建一份锁。旧阶段锁在兼容期保留，不拿来共同管理新工程。

练习包先提供最小可运行骨架，不提前实现后面 48 课的答案。初期业务文件没有提前散布 React、Query 或复杂抽象。C01 开始页提供一次性 Node 环境与启动说明，明确现成服务脚本可先照做；C17–C20 再解释运行时和工具机制。安装说明实施时查官方兼容版本，本次不升级依赖。

| 拟定命令（均在 `labs/inventory/`） | 行为与限制 |
| --- | --- |
| `npm ci` | 同一发行版初次安装；跨 Lab 不反复执行。发布包包含完整锁文件；下载体积与首次安装耗时要在试做时测量 |
| `npm run lab -- status` | 显示当前课、入口、上次检查及下一步，不根据目录时间猜测完成状态 |
| `npm run lab -- start C03` | 选择任务、列出本课文件与验收，写本地任务位置；不复制答案、不替换已有源码 |
| `npm run lab -- dev` | 根据当前课启动相应界面并打印准确 URL；同一界面跨课保持服务；换到 UI5 时可明确重启服务，不搭复杂跨框架代理 |
| `npm run lab -- check C03` | 检查学员实际工作文件的本课行为及受影响的前置行为；失败打印输入、期望与实际，不只显示通过数量 |
| `npm run lab -- report` | C17 后生成当前数据的 Node 报表 |
| `npm run lab -- build` | 构建当前交付目标；C46 明确区分站点 `/js_web/` 与演示嵌套路径的 base |
| `npm run lab -- compare C03` | 按需显示与该课参考解的差异，只读；网站答案默认折叠 |

命令入口使用普通 Node 脚本，显式调用已有 Vite、Vitest 或 UI5 工具。不要建设在线 IDE、代码沙箱、账号系统或新的教学框架。参考解不在学员正常启动时被 import。

C18 的清单/锁不一致实验、C19 的其他包管理器实验，由入口在 `.lab/sandboxes/` 建隔离副本并打印位置；学员仍从工作区发起。这两个安装实验属于课程知识点，不影响主练习的锁文件。实验命令与版本要在实施时重新核验。

## 6. 质量门禁与改版风险

每课发布前：运行该课现有固定输出例子 `npm run examples -- cNN`，执行新 Lab 对应检查和浏览器操作，再在网站根目录运行 `npm run lint:lessons`、`npm run check`、`npm run build`。命令未落地前不能把方案当作已通过；旧例子迁为参考后仍按现有构建路径验证。编写时先读本课范围、上一课终态及写作规范，先写可运行增量，再写正文。

更新 STATUS 后按 AGENTS.md 在 main 正常提交本次相关改动，推送前检查远端，保留双方内容处理冲突，不强推。推送后等对应 Pages Actions 成功，并确认课程线上地址返回 200；失败继续修复或如实报告。用户当次要求本地草稿时遵从该要求。

实施阶段还必须满足以下行为检查：

- 每章有且只有一个必做项目增量，预测题/修错题围绕它；机制对照可以多个，独立运行另一个 demo 的必做指令为 0（C18/C19 隔离工具实验由统一入口承载）。
- 48 行清单连续且无重复，Lab 所属、前置、快照、文件、正文命令、验收和故障编号互相对应；C01–C48 的 URL 不变。
- 固定输入、空值、非法输入与主要错误场景的完成快照通过；起点的预期失败写明。每课 README 写真实执行范围，不把资料核对写成运行通过。
- 双栏每侧一个代码块分别计数，导入代码也计行数；普通课 8,000 字/16 块、难点课 10,000 字/20 块及每块 25 行上限保持。不要通过把正文塞进组件参数绕过 lint。
- 代码对照展示相同输入和可比较目标；不同机制明确说明。Java 完整例子可独立编译，React 展示的是渲染结果或事件行为，不伪装成普通 Node stdout。
- 新的脚本防覆盖、进度兼容、真实文件校验、快照可重建属于必要测试；排版文本变动只做文档检查与视觉审阅，不增加镜像实现的测试。
- 样式/组件变更和每周节点做全套视觉验收：360/768/1280px、亮暗、键盘、两侧复制、折叠答案、D2、禁用 JS、搜索三词。普通课仍不重复全站视觉巡检。
- 学习包从下载到首次打开、暂停后恢复、在非空目录尝试恢复、切换 UI5、生产子路径与导入旧 F1 进度均需实测；记录安装体积/时间，不预先承诺秒级启动。

## 8. 业务契约与框架边界

以下是实施前需要固定并写测试的接口。C16 才完成模块化；C01–C15 可以在同一个 `inventory.js` 逐步写出这些能力，不提前要求读懂架构。

| 契约 | 统一行为 |
| --- | --- |
| 原始商品 | 唯一来源 `examples/shared/products.json`；练习包和静态请求资产由其生成，检查字节/结构一致；任何示例编辑均使用独立副本 |
| `parseStock(text)` | 表单文本去空白后必须非空，结果是 0–99,999 的整数；非法返回明确错误，不能把空输入存成 0 |
| `parsePriceCents(text)` | 按元输入，最多两位小数；转换为非负安全整数分。前端接收 JSON 时仍校验，不依赖 TypeScript 或 HTML 属性代替业务规则 |
| `validateProduct(product)` | 按 §3.1 校验完整字段，返回可定位到字段的错误；边界过大金额的表示范围在转换处明确 |
| `summarize(products)` | 返回总库存、总价值、售罄与低库存数；低库存只算 1–5，空列表各项为 0；超安全整数的汇总应报范围错误而非静默失真 |
| `updateStock(products, id, stock)` | 返回新数组和被改商品的新对象，其余项可复用；不改输入。撤销保存旧值或独立快照 |
| `Inventory` | C07 的 class 用于解释 this/原型与封装；React state 保持普通数据，复用纯函数，不把可变实例塞进 state 后直接改字段 |
| 请求与持久化 | 接口统一使用 id；浏览器只访问静态资源或浏览器内 mock。可注入延迟/失败用于确定性检查 |

C14 的原生存储与 C31 的 React 存储使用不同命名空间、同一商品快照格式；通过显式导入导出交换。C32 引入 Query 后，mock repository 负责数据与持久化，Query 负责其请求缓存；React state 只保留 UI/草稿状态，避免三份可写商品数据。手工请求实现保留为课程参考，不与 Query 同时写同一页面的数据。

OpenUI5 的 `sap.ui.define` 与 ESM 不是同一种模块加载方式。实施者先做共享规则的构建适配试验：把纯函数编译为 UI5 能加载的模块，生成物只读，用相同测试向量验证两端。不得直接把 ESM 粘进 Controller，或手工抄出另一份逐渐漂移的校验逻辑。该桥接放在工程工具层，学员只跟做 View/Controller/Model 的必要改动。
