### 3.1 固定样例数据

权威来源为 `examples/shared/products.json`；练习数据由它派生。同一 id 的起始值一致，补货/编辑使用独立副本。

| id | name | category | stock | priceCents | tags |
| --- | --- | --- | --- | --- | --- |
| P001 | 机械键盘 | 外设 | 12 | 39900 | 热销 |
| P002 | 无线鼠标 | 外设 | 0 | 12900 | — |
| P003 | 27 英寸显示器 | 显示器 | 7 | 159900 | 新品 |
| P004 | USB-C 扩展坞 | 配件 | 3 | 29900 | 热销、新品 |
| P005 | 显示器支架 | 配件 | 25 | 19900 | — |
| P006 | 降噪耳机 | 音频 | 5 | 89900 | 热销 |

固定结果：6 种商品、总库存 **52**、总价值 **2,634,800 分**；售罄 P002；低库存只算 1–5 件，为 P004/P006；分类计数 2/1/2/1；标签去重为热销、新品。

字段规则：id 为 `P` 加三位数字且唯一，新建自动生成；name 去首尾空格后 1–40 字；category 四选一；stock 为 0–99,999 的整数；priceCents 为非负安全整数，元输入最多两位小数；tags 为字符串数组。空白库存非法，0 合法。JSON 解析后继续校验字段；超安全整数的汇总报范围错误。

## 4. 教程写法：先让读者做得出来

写课前读完 [CONTENT_GUIDE](CONTENT_GUIDE.md)，再读 [CURRICULUM](CURRICULUM.md) 对应行与 [错误矩阵](DEBUG_TESTING.md#revision-v2-errors)。本计划与 [Lab 设计](../labs/README.md) 决定执行范围；其余文档保留知识和技术细节，不另生任务队列。

1. 每课一个主要学习任务。功能课是项目增量；选型/工具/复盘课可以是观察、实验或判断，不强造业务函数。
2. 写清“从哪个状态开始、修改哪个文件哪个位置、怎么操作、应该看到什么”。小片段必须交代插入/替换位置、导入和调用关系；不能靠生成脚本里未展示的组装知识才能完成。
3. 默认修改 1–3 个文件；模块拆分列完整搬移清单。长机械性脚手架可在起点预置并说明，核心教学逻辑由学员完成。完整答案按需展开。
4. Java/JS 双栏用于真实迁移差异，每课 **0–3 张有价值的卡片**。没有合适的 Java 机制时，保留“Java 程序员先看这里”，用短说明引入新机制；不强造 Java CSS、Hooks 或 UI5 等价 API。
5. 每课选一个主错误走完现象→工具→证据→原因→修复→确认。预测、修错、项目验收围绕同一任务，不叠加三套作业。
6. 保留机制深度与篇幅门禁：普通课 ≤8,000 字/16 块，难点 ≤10,000 字/20 块，每块 ≤25 行；双栏和导入片段照常计数。正文不给作者验证日志和内部编号。
7. 页首标真实验证状态；未运行片段就近标注，明细留 `examples/cNN/README.md` 并链接阶段记录。标准/版本/API 先查官方，补入 SOURCES。

### 7.2 如何真正并行并保证课程衔接

1. **主 agent 先固定基线**：读 AGENTS→STATUS→PLAN→Lab 设计与本阶段规范，检查 Git，保留并审阅继承改动。记录四路文件归属、起点、接口和验收向量；这是派发清单，不重做规划。
2. **四个隔离工作副本**：各路使用主 agent 分配的独立目录，提示词写明绝对路径；基线须包含本次规划及已接管的未提交文件。不能只从 HEAD 创建 worktree 而漏掉 C21–C31 等成果；也不能四路同时在主目录改 App、锁、catalog 或运行会写生成物的 build。使用临时副本或 worktree 均可，不带入凭据/个人数据。最终只集成各路拥有的增量文件，不能整目录覆盖。
3. **先约定交接接口，再并行实现**：A 重点约定 C24 商品 state、C28 reducer/草稿/句柄与 C32 repository/Query 的导出和数据归属；B 复用 A 的 C36 core/repository 与共同 P004 验收向量。后段可以先核查官方资料、编写正文/组件/测试并使用显式临时契约夹具；夹具仅在隔离验证中使用，不能混进正式起点或算作集成已通过。
4. **同时派发**：连续发出四个 `subagent` 后台调用，均为 `agent: "general"`、`model: "openai/gpt-6.1-sol#max"`、`background: true`，不等待第一路完成才启动第二路。每份提示词带阶段/编号、目录、文件所有权、交接接口、继承成果、验收/交稿要求，以及“不得提交推送、不得另派子 agent”。保存四个 sessionID。
5. **主 agent 协调但不抢写**：可只读审阅已交稿内容、整理集成问题；依完成通知接收各路结果，不轮询。上游交稿后，由主 agent 提供已确认的交接快照/接口变更，优先继续原下游 session 修订；四路是并行工作，不意味着有依赖的最终集成也能同时完成。
6. **按依赖集成并返修**：四路首轮交稿后，A 按 1→2→3→4 串起真实相邻快照，B 按 C37→C44 接入四个并列 adapter，C 集成代码/导航/包后做全站终验。主 agent 处理少量接线与共享元数据，实质问题退回原负责人；相互独立的返修继续并行。各路必须针对最终接续结果补验，局部夹具通过不能代替它。

### 7.3 四路全部结束后才向用户交接

- 每路交回：改动文件/补丁、交接接口、测试命令与实际结果、错误红绿证据、临时夹具/未执行项/阻塞、共享文件修改建议，结论为“待主验收”。不能将 implemented 直接等同 migrated/已发布。
- 主 agent 等 **1/2/3/4 四路全部返回，连同返修任务结束**，审阅集成 diff，并在最终集成结果上执行 §6 的独立教学验收与发布门禁。四路各自测试绿仍需集成验证；最终阶段记录由主 agent 汇总四路结果、sessionID 与验收证据。
- 某一路失败，主 agent 继续该 session 返修；会话确实无法恢复时，记录原因后替换该编号，原任务停止后再启动替代者，同时活跃子 agent 不超过 4 个。环境无法支持四路时报告阻塞，不伪称已并行完成。
- 主 agent 完成提交、Pages 等待与线上核验后，**一次最终回复**汇总四路交付、集成/发布结果和下一窗口提示词。运行中可简短汇报进度，但不能某一路完成就提前给最终结果、要求用户清上下文或启动下一阶段。
- 未完成时如实列明卡住的编号与剩余工作，确认没有仍在写文件的子任务再交接，下一窗口继续同阶段。成功后停在阶段边界，由用户清理会话上下文并新开窗口；C 成功即结束本轮改版。
