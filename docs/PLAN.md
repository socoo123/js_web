## 2. 不变的边界

### 2.1 「核心内容不变」的含义

逐课保持不变：课号、标题、slug、URL 与已有锚点（改标题时保留兼容锚点）；所属学习日和 4 周/8 周节奏；概念节的知识点；Java 对照的主题；主错误；练习考查的能力；本课的 Lab 任务与验收数字；固定数据和字段规则。

可以改：措辞、段落拆分、节内顺序、呈现组件、操作说明放在哪里、Lab 页结构、首页、路线页和外观。**L5 是唯一允许更换任务场景的 Lab**：C45–C48 的知识范围（全链路调试、静态构建与 Pages、测试选择、总复盘）不变，练习改为围绕真实后端进行。

每课改写交稿时附一张「核心对照清单」：改写前后的概念节知识点、Java 对照主题、主错误、练习考点、验收数字逐项对应。缺一项即退回。

### 2.2 继续有效的约束

- 读者会 Java、初学前端；中文教学；HTML/CSS/浏览器不跳过；调试工具与 UT 必修；TypeScript 只做桥接和选修。
- Astro + Starlight + MD/MDX + 少量 React islands；站点用 npm 和根目录唯一的 `package-lock.json`；部署到 `socoo123/js_web` 的 `/js_web/` 子路径。
- 机制图只用 D2（保留 14 张源码与 SVG）。§5 的「效果截图」是脚本从参考快照真实运行后拍下的结果，不是示意图。
- Pages 上只有静态文件、静态数据、浏览器内 mock 和本地存储。L5 后端只在学员本机运行。
- CONTENT_GUIDE 第 1–15 节继续有效，只按 §4 调整呈现；篇幅上限（普通课 8,000 字/16 块，难点课 10,000 字/20 块，单块 25 行）不放宽。
- 诚实标注：页首写真实验证状态；未运行的例子就近标注；验证明细写在 `examples/cNN/README.md` 和阶段记录里。

### 2.3 不做的事

不增加课数、Lab 数、业务字段；不换框架；不做在线 IDE、账号、云同步或服务端渲染；Pages 不跑后端；不接真实 SAP。L1–L4 的参考实现代码只在截图、演示或回链确实需要时做定点修正，已发布快照和下载包字节不变。

### 3.2 Lab 主导、课文回看

五个 Lab 的课程范围和起点不变：L1 C01–C10（起点 C00）、L2 C11–C20（C10）、L3 C21–C36（C20）、L4 C37–C44（C36）、L5 C45–C48（C44）。变化在于**学习从 Lab 页出发**：

```text
Lab 页的当前步骤 → 点「先读」跳到课文的某一小节 → 读完点「返回 Lab」
→ 在自己的 inventory/ 动手 → 对照步骤里的效果截图和验收 → 勾选完成 → 下一步
```

**Lab 页结构**（五页统一）：

1. 目标卡：这个 Lab 做出什么，配完成后的效果截图；有在线目标演示的给出链接（见 §5.4）。
2. 步骤时间线：每课 1–3 步。每步写明目标、「先读」（1–3 个课文小节锚点，并说明为什么读）、改哪些文件、怎么操作、效果截图或预期输出、验收、检查命令、提示和参考答案（折叠）。
3. 收尾验收清单，可逐项勾选。
4. 起点、暂停、恢复、升级说明，默认折叠。

**回看规则**：L2–L5 的步骤，凡用到前面课的知识，就链回那一课的具体小节（例如 L5 写请求错误处理时链回 C13 与 C30）。每课至少被一个步骤引用；每个锚点在构建时校验存在。

**课页侧**：顶部 `LabBar` 显示「L3 · 第 3 步 / 共 16 步 · 返回 Lab」。从 Lab 的「先读」进入时带 `?from=<步骤 id>`，页面浮出「返回 L3 第 5 步」。禁用 JS 时仍有指向 Lab 页的静态链接。

**数据**：每个 Lab 一个文件 `labs/steps/l1.json` … `l5.json`（一个 Lab 只由一人负责，减少并行冲突）。字段至少包括 `stepId`、`lessonId`、`title`、`goal`、`read[{lessonId, anchor, why}]`、`files`、`actions`、`preview`、`acceptance`、`check`。`labs/catalog.json` 仍是课程关系的唯一来源，步骤文件只引用课号，不复制 catalog 字段。

**进度**：Lab 步骤勾选并入 F1，格式升为 `{"version":2,"completed":[...],"labSteps":[...]}`。导入同时接受 v1 与 v2；备份、损坏恢复、跨标签同步和 64 KB 限制照旧，测试同步扩展。勾选只表示学员自己确认，不表示本地检查已通过。

### 3.3 L5：提供后端，学员写前端

#### 后端（作者提供，学员不需要写）

- 位置：`labs/inventory/server/`，从 L5 起点（新发行版的 C44 快照）开始出现；更早的旧发行包不变。用 Node 24 自带的 `node:http` 与 ESM 实现，不新增依赖。
- 启动：`npm run lab -- api`，只监听 `127.0.0.1:8070`，终端逐行打印 `方法 路径 状态 耗时`，作为全链路排错的服务端证据。
- 数据：持久化到 `.lab/server/products.json`，首次启动从 `data/products.json` 生成；先写临时文件再改名；数据文件损坏时拒绝启动，并提示 reset。
- 规则：服务端自带一份只读的校验/统计规则，与参考 `src/core` 同源生成；**不 import 学员可改的 `src/core`**，学员的 bug 不会弄坏后端。
- 错误格式：统一为 `{"error":{"code","message","fields?","current?"}}`。
- 跨域：默认不发 CORS 头，开发走 Vite 代理同源访问；设置 `LAB_API_CORS_ORIGIN` 才允许指定来源。C45 用它讲 CORS 的现象与原因。

| 方法与路径 | 作用 | 成功 | 主要失败 |
| --- | --- | --- | --- |
| `GET /api/health` | 存活检查 | 200 `{"ok":true}` | — |
| `GET /api/products` | 列表；参数 `q`、`category`、`stock=low\|out`、`sort=id\|name\|stock\|-stock`、`page`（从 1 起）、`pageSize`（1–50，默认 20） | 200 `{items,page,pageSize,total,summary,totals}` | 400 参数非法 |
| `GET /api/products/:id` | 详情，带 `version` | 200 | 404 `NOT_FOUND` |
| `POST /api/products` | 新建，id 由服务端分配 | 201 + `Location` | 400 `BAD_JSON`；422 `VALIDATION` + `fields` |
| `PATCH /api/products/:id` | 部分修改，必须带 `If-Match: "<version>"` | 200 新商品 | 428 缺版本；409 `CONFLICT` + `current`；422；404 |
| `POST /api/products/:id/restock` | `{"quantity":3}` 补货 | 200 | 422；404 |
| `DELETE /api/products/:id` | 删除 | 204 | 404 |
| `POST /api/_lab/reset` | 恢复固定数据 | 204 | — |
| `POST /api/_lab/faults` | 让指定方法和路径接下来 N 次返回某状态或延迟 | 204 | 只在本地，供排错与测试 |

`summary` 统计筛选后的**全部**结果（不受分页影响），`totals` 统计全部商品。分页的一页不能冒充全量统计。

**契约向量**（`labs/inventory/tests/server/` 用 `node --test` 覆盖）：初始列表 6/52/2634800；`stock=low` 得 P004/P006，summary 为 2/8/539200，totals 仍为 6/52/2634800；PATCH P004 库存 8 后 totals 为 57；用旧 version 再 PATCH 得 409 且带 current；空白库存得 422，`fields.stock` 有值，0 合法；新建 P007 后 7/55/2634887；DELETE 后 404；reset 后回到初始值。

网站新增 `src/content/docs/labs/api.md`「L5 后端接口」：每个接口给出请求、响应示例和常见失败，面向学员。

## 4. 课文改写规则（阶段 1 写入 CONTENT_GUIDE 第 16 节）

### 4.1 每个概念节的节奏

**一句主张 → 代码 → 效果 → 为什么（≤3 句）→ Java 对照一句 →（可选）「记住」一句。**

「效果」三选一，必须紧跟代码：输出面板（Console/终端）、真实页面截图（可切亮暗或宽度）、交互演示。两个代码块之间不能既没有效果，也没有解释。

### 4.2 降低阅读密度

- 一段最多 3 句，约 120 字以内；一句只讲一个条件或一个结论。
- 一段的行内代码不超过 3 处；文件路径、命令放进任务卡或代码块，不夹在长句里。
- 验收数字（12→15、52/2634800）放在效果面板和验收清单里，不塞进说明段落。
- 不写一连串分号的长句；需要并列时改成列表。
- 术语第一次出现时，补一句白话解释。
- 下载、恢复、端口、Ctrl+C、`npm ci`、`compare` 等操作细节只写在 Lab 页和任务卡的折叠区，课文里不重复。

### 4.3 页面结构

必需的二级标题不变（lint 依赖）。页首由 `LessonHeader` 显示周/天、时长、前置、真实验证状态，`LabBar` 显示所属步骤。「这一课解决什么问题」不超过 4 句，加一张「完成后的效果」和 3 条「学完你能」。「先猜一猜」改用 `Predict`，答案点击才显示。「项目进度」保留标题与锚点，内容改成：本课让 Lab 第几步可以勾选、效果截图、下一步链接。

### 4.4 效果覆盖要求

每个概念节至少 1 个效果。DOM、CSS、React、UI5 的课每课至少 2 张真实截图或 1 个交互演示。调试证据优先用文本面板呈现；手工 DevTools 截图每课最多 1 张，并在截图清单里标 `manual` 和日期。

### 4.5 改写示例（用来校准尺度）

C23 第 1 节原文：

> 初次渲染的 stock 是 P001 的 12；之后 React 使用保存的状态，初始参数不会在每次渲染都重置它。以后即使 product prop 改变，也不会自动用新 product.stock 同步这份局部 state。`add` 用共享的不可变更新函数取得下一库存，超过范围时保留原值。updater 不改 props，也不在里面写存储或发请求。

改写后：

```mdx
<Effect kind="demo" demo="c23-first-render" caption="点一次 +1：12 → 13" />

**记住：** `useState(12)` 里的 12 只在第一次渲染时使用，之后 React 用它保存的值。

所以 product 换了，这份 state 不会自动跟着换。
```

「updater 保持纯粹」在第 3 节已经讲过，这里删掉，不重复。

### 4.6 lint 跟进

阶段 1 扩展 `scripts/lint-lessons.mjs`：把 `Predict` 计为「先猜一猜」；新组件里的代码计入代码块与行数；新增警告：段落过长、行内代码过密、代码块后没有效果。阈值在阶段 1 用 C03/C15/C23 试跑后确定，写进 CONTENT_GUIDE 第 16 节；哪些升为 error 由阶段 1 主 agent 决定，并记录在阶段记录里。

| `LessonHeader` | 课页头：周/天、时长、前置、验证状态、所属 Lab | 静态显示 |
| `LabBar` / 返回浮标 | 显示所属步骤；带 `?from=` 进入时浮出「返回第 N 步」 | 静态 Lab 链接 |
| `LabSteps` | 渲染 `labs/steps/lN.json`：步骤卡、先读链接、勾选、进度环 | 步骤全部可读，隐藏勾选 |
| `Predict` | 问题加代码，点击揭晓答案 | 原生 details |
| `Effect` | `console` / `terminal` / `page`（截图，可切亮暗和宽度）/ `demo`（嵌入 island） | 显示静态输出或截图 |
| `RunSnippet` | 只运行受控片段（来自 `examples/cNN` 且有 expected 输出）；放在 `sandbox="allow-scripts"` 的独立 iframe 里执行，捕获 console，2 秒超时；可编辑、重置、对比预期。只用于纯 JS 课 | 显示已验证的输出 |
| React 演示 | `client:visible` 的 island，只用固定数据，每课最多 2 个。首批：C12 事件循环步进、C23 更新队列、C24 key 身份、C26 状态保留与重置、C29 Effect 生命周期日志、C30 请求竞态（可调快慢） | 显示截图与文字说明 |
| `CodeCompare` / `LessonTask` | 保留职责，按新视觉重做；任务卡精简 | 照旧 |

性能预算：不用 island 的页面不加载 React；单页新增 JS（gzip）不超过 80 KB。复制、键盘操作、焦点、`aria-live` 和无 JS 阅读维持 V2 标准。

### 5.4 数据文件与生成链

- `labs/previews/cNN.json`（每课一个文件）声明截图：使用哪个快照、入口、操作序列、视口、主题。`scripts/capture-previews.mjs` 用 `labs/inventory` 里已锁定的 Playwright 拍摄，输出 WebP 到 `src/assets/previews/` 并提交。清单记录源码校验值；源码变了而截图没重拍时，`check:build` 报错。
- `labs/demos.json` 与 `scripts/build-demos.mjs`：把参考快照以 mock 数据构建成「Lab 目标演示」，放在 `/js_web/demos/l2/`、`l3/`、`l5/` 等路径（L1 用截图，L4 的 UI5 用截图）。不占用 `/js_web/demos/inventory/`，那是 C46 里学员自己构建的目标路径。
- `RunSnippet` 的片段直接复用 `examples/cNN/*.js` 和 `.expected.txt`，已由 `npm run examples` 验证。
- 接入 React islands 需要在根依赖加 `@astrojs/react`、`react`、`react-dom`，版本先查官方并核对与 Astro 7 的兼容性，记入 SOURCES。

## 7. 四个子 agent 并行，主 agent 汇总验收

**数量是硬要求：每阶段 4 个实现子 agent + 1 个主 agent。** 主 agent 不算在四个里，也不能串行跑四次冒充并行。

- **模型**：2026-11-06 用户指定四个子 agent 都用 **Opus 5.5 1M Extra High**（与主 agent 相同）。Cursor 用 `Task` 工具，`model: "claude-opus-5-5-xhigh"`、`run_in_background: true`；当日可用列表里只有这个 Opus 5.5 Extra High 条目，没有单独标 1M 的名称。若启动时列表出现明确标 1M 的 Opus 5.5 Extra High，就用它；在其他工具里运行时选同一模型。启动前核验，目标模型不可用就问用户，不静默换模型，也不减少路数。用户在启动语句里另行指定时以启动语句为准。
- **隔离**：每路一个独立工作副本。Cursor 可用 `best-of-n-runner`（自带 git worktree），OpenCode 用主 agent 分配的临时目录。worktree 从 HEAD 创建，所以派发前主 agent 先把基线（含本计划和已接管的改动）提交到本地 main。不带入凭据和个人学习数据。
