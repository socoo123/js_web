# 总计划（2026-10-18 更新）

恢复关键词：**JS_WEB_START**。本文件是建站和写课的总约束。怎么写课看 [写作规范](CONTENT_GUIDE.md)，每课的范围看 [课程大纲](CURRICULUM.md)，当前进度看 [STATUS](STATUS.md)。用户当次提出的新要求优先于本文件。

## 0. 为什么修订

C01–C05 已经上线，内容基本准确，但读起来像审计报告，不像教程。下表是去掉代码块后统计的实测数据：

| 问题 | C01–C05 的情况 | 修订后的约束 |
| --- | --- | --- |
| 太长 | 正文每课 12,000–16,500 字，按每分钟 300 字估算，光读完就要 40–55 分钟 | 5,000–7,000 字，上限 8,000（难点课 10,000） |
| 验证信息写进正文 | 每课 10–14 处「验证状态」，内部编号 S01/V03/E02，浏览器补丁号，作者用什么工具跑的 | 页首写一行；明细只写在 `examples/cNN/README.md` |
| 防御式免责 | 每课 33–61 句「不能 / 不要 / 不代表 / 不宣称……」 | 先正面讲规则；例外集中写，提示框每课 ≤ 3 |
| 链接不适合初学者 | 每课 8–14 条 ECMA-262 规范链接，MDN 0 条 | 正文链接 MDN / react.dev / 官方文档；规范只放延伸阅读 |
| 示例难用 | 一个 60 行片段测 8 种行为；在 Console 粘贴，每换一个文件就要刷新 | 一段代码一个概念、≤ 25 行；C06 起纯 JS 例子用 `node` 运行 |
| 贯穿项目没有贯穿 | 每课都是孤立片段，每课的库存数据都不一样 | 固定样例数据，分阶段的项目目录，每课往前推进一步 |
| 流程太重 | 每篇都做 1280/360 宽度、亮暗模式、搜索等全套人工验收；STATUS 有 16KB 日志 | 每课只过最小门禁，全套视觉验收每周做一次；STATUS 每课一行 |

根本原因：原规则反复强调「不能声称……」，执行者就把写给审阅者的自证写进了给学员的正文。本次修订保留诚实标注的要求，只改它的记录位置，并用 lint 脚本把篇幅和措辞变成可以检查的规则。

**范例课**：C03 已按新规范整篇重写（正文约 7,500 字、16 个代码块、1 张 D2 图，示例全部带 `.expected.txt`）。写新课或重构课程之前，先通读 C03 的正文、`examples/c03/` 和 `diagrams/c03-value-boundary.d2`，按同样的结构、密度和语气写。

## 1. 学员与目标

学员会 Java，没系统学过前端。每天 3–4 小时，4 周主线，8 周慢速版。

学完能做到：

1. 讲清 JavaScript、ECMAScript、引擎、浏览器、Node、Bun、npm/Yarn/pnpm 各自负责什么。
2. 读写现代 JS：类型、作用域、函数与闭包、this 与原型、模块、异步。
3. 按业务选 Array/Object/Map/Set，能用 JS 写栈、队列和树遍历。
4. 理解浏览器的页面、事件、请求、存储和 CSS 布局，会用 DevTools 定位问题。
5. 用 Node + npm 建立可复现的项目，读懂 package.json、锁文件和构建产物。
6. 用 React 完成表单、状态、请求、路由、错误处理，并写有意义的测试。
7. 分清 SAP 的几套 UI 技术，完成 OpenUI5 和 React + UI5 Web Components 的最小业务示例。
8. 选用一个开源组件库，把静态前端应用发布到 GitHub Pages。
9. 用断点、Network、React DevTools 和测试失败信息定位问题；用 Vitest/RTL 写行为测试，知道 Jest 和 Playwright 的定位。

不追求高级算法、完整 SAP 后端、SSR 和大型架构，这些放进选修。

## 3. 贯穿项目：库存管理

所有课程用同一个业务和同一份数据，学员只需理解一次业务。

### 3.1 固定样例数据

所有例子统一使用这份数据（C01–C05 重构时已改用）。可以只取子集；同一个 id 的起始字段值必须一致，示范编辑和补货时可在此基础上更新。

| id | name | category | stock | priceCents | tags |
| --- | --- | --- | --- | --- | --- |
| P001 | 机械键盘 | 外设 | 12 | 39900 | 热销 |
| P002 | 无线鼠标 | 外设 | 0 | 12900 | — |
| P003 | 27 英寸显示器 | 显示器 | 7 | 159900 | 新品 |
| P004 | USB-C 扩展坞 | 配件 | 3 | 29900 | 热销、新品 |
| P005 | 显示器支架 | 配件 | 25 | 19900 | — |
| P006 | 降噪耳机 | 音频 | 5 | 89900 | 热销 |

各课结果必须一致的参考值：总库存 **52**；库存总价值 **2,634,800 分**（26,348.00 元）；售罄 1 个（P002）；低库存（1–5 件）2 个（P004、P006）；分类计数为外设 2、显示器 1、配件 2、音频 1；去重后的标签为热销、新品。

字段规则（原生表单、React、UI5 三个版本共用）：

- `id`：`P` 加 3 位数字，新建时自动生成。
- `name`：去掉首尾空格后为 1–40 个字符。
- `category`：外设、显示器、配件、音频四选一。
- `stock`：0–99,999 的整数。
- `priceCents`：0 或正整数。表单中按「元」输入，最多 2 位小数，保存时换算成分。
- `tags`：字符串数组，可以为空。

固定数据已保存在 `examples/shared/products.json` 和 `examples/shared/products.js`（ESM 导出）。

## 5. 写一课的流程

1. 读 CURRICULUM 中本课那一行和本周的写作范围，再读上一课的「小结」和「项目进度」。第一次写课时先通读范例 C03。
2. 涉及版本、命令或新 API 时，先查官方文档，并在 SOURCES 记录日期。
3. **先写例子**：`examples/cNN/` 里的文件和 `.expected.txt`，运行 `npm run examples -- cNN` 直到通过。项目阶段目录同步更新。
4. 按 CONTENT_GUIDE 的模板写正文，代码块从 examples 中原样复制。
5. 运行 `npm run lint:lessons`、`npm run check`、`npm run build`。超长就删内容。
6. 按 CONTENT_GUIDE §14 自查。
7. 更新 STATUS：「已发布课程」加一行，改「下一步」。
8. 按 AGENTS.md 提交并推送，等 Actions 成功，确认新课线上地址返回 200。

## 7. 多 agent 并行规则

- C06 由主 agent 亲自写，不并行。用户确认风格之后，每批最多并行 3 课。
- 给子 agent 的提示必须包含：课号、CURRICULUM 中的那一行和本周写作范围、CONTENT_GUIDE 和范例 C03 的路径、上一课的小结和项目进度、§3.1 的固定数据、字数上限。
- 同一批里后一课依赖前一课的项目代码时（例如 C08 依赖 C07 的 `inventory.js`），主 agent 先定好函数名和签名，写进每个子 agent 的提示，再开始并行。
- 子 agent 只写本课的正文、`examples/cNN/`、本课的 D2 图和对应的项目阶段文件。不改 `docs/`、脚本、站点配置和其他课。
- 主 agent 合并前跑全部门禁，通读每课，检查术语、数据和前后衔接是否一致，改好后统一提交。
