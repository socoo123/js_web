Java 程序员先看这里

同一份输入，左右看写法

输入框给你的是文本。先转换，再校验，最后参与库存计算。

共同输入：库存 12，补货文本 "3"

JavaRestock.java · main 方法片段
String input = "3";
int stock = 12;
int amount = Integer.parseInt(input);

System.out.println(stock + amount);
输出15
JavaScriptinventory.js · 转换片段
const input = "3";
const stock = 12;
const amount = Number(input);

console.log(stock + amount);
输出15

记住这一点：合法整数文本都能转换，但边界不同：Java 解析空字符串会抛异常，JS 的 Number("") 得到 0。

先猜一猜：如果跳过 Number，直接执行 12 + "3" 呢？JS 会拼接文本，得到 "123"。下面的任务还要检查空输入，避免把“没填”当成合法的 0。

常见错误：没有报错，库存却变成了 123

在 Sources 给补货计算行设断点，点击补货。在 Scope 查看 amount，再求值 typeof amount：它是 string。修复转换后重复点击，库存应从 12 变成 15；继续检查空白和小数输入。

自己尝试 · 在当前文件里完成

  1. 找到库存输入转换的位置，先对文本执行 trim() 并拒绝空白。
  2. 转换后检查整数与范围，再把有效数量交给已有补货逻辑。
  3. 用 3、空白、3件、-1、1.5 重复操作，确认无效输入不改变库存。
提示：转换成功不等于输入合法

先保留原始文本用于空白检查，再看 Number.isInteger 与范围。库存为 0 本身是有效业务值；初始输入校验与补货后的总库存范围都要满足要求。

参考答案：输入边界的关键改动
const raw = input.trim();
const amount = Number(raw);
if (raw === "" || !Number.isInteger(amount)
    || amount < 0 || amount > 99999) {
  throw new Error("请输入有效数量");
}

这里只展示输入校验。实际保存还应校验补货后的总库存不超过 99,999；完整参考解应使用本课固定快照。

LAB 03　/　React 库存应用

C23 连续更新，为什么只加了一次？

现在仍然给同一件机械键盘补货。Java 中连续三次加一会得到 15；React 中的三次 setter，需要先看它们读取的是哪一份状态。

把“补三件”接到现有商品卡片

同一个库存项目

修改 src/react/StockActions.jsx 与 App 的事件回调。

开始：P001 库存 12完成：一次补三件 → 15；延迟操作也不丢更新

相同目标，不同更新机制

共同目标：从 12 连续加三次 1

JavaUpdate.java · main 方法片段
int stock = 12;
stock += 1;
stock += 1;
stock += 1;

System.out.println(stock);
当前变量的输出15
React / JavaScriptStockActions.jsx · 错误事件片段
// 有问题的写法：三次都读取 12
// 当前渲染的 stock === 12
setStock(stock + 1);
setStock(stock + 1);
setStock(stock + 1);
下一次渲染显示13

差异在这里：Java 片段立即修改局部变量；React 事件读到当前渲染的快照，三次都提交 13。setter 会请求更新。

先猜一猜：第一次调用 setStock 之后，在同一个事件函数里读 stock，会得到 12 还是 13？它仍是 12。下一次渲染得到的新 state，不会改写这次回调中的局部值。

提示：下一步的更新要基于队列里的待处理状态

函数式更新会接收前一步的结果。把“设为当前快照加一”改成“在待处理值上加一”，再连续提交三次。

参考答案：三次函数式更新
setStock(current => current + 1);
setStock(current => current + 1);
setStock(current => current + 1);

从 12 开始，队列依次得到 13、14、15，下一次界面显示 15。当前事件回调中的 stock 仍然是 12。再验证延迟补三件期间立即补一件，最终应为 16。

这个片段展示 state 更新机制。完整课将把它接回商品集合，并提供断点观察、Hooks 规则和当前工作区的行为检查。
