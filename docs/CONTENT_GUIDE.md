# 教学与示例规范

这是一套给 Java 程序员的中文入门课程。语言可以深入，解释必须从读者已知的模型出发，且明确类比哪里会失效。

## 每课结构

1. **问题与目标**：这节解决什么困惑，学完能做什么；列前置课号与阅读/练习时间。
2. **Java 对照**：使用读者熟悉的变量、对象、集合、异常、JUnit 等概念建立起点。
3. **JS 机制**：解释行为原因，避免只背语法。
4. **代码与结果**：完整必要文件、环境、步骤、输入、预期输出；长例子按阶段拆开。
5. **易错例子**：至少一个真实易错点，说明触发条件和如何定位。
6. **自己尝试**：必做练习、操作步骤和验收标准；扩展题可跳过。
7. **提示与答案**：渐进提示、折叠答案、解释取舍；不能只贴最后代码。
8. **项目连接**：把概念用于同一库存应用。
9. **回顾与来源**：能独立回答的几个问题，官方资料与核查日期。

普通课保持主题集中；React 状态、Effect、请求、测试等难点可以较长，但按清楚的阶段组织。不要通过硬凑字数或重复 Java 基础制造“详细”。

## 例子的状态和操作方式分开

操作标签：

- **讲解示例**：用于阅读、预测输出和说明机制。
- **自己尝试 · 浏览器 Console**：无需额外工程，注明必要浏览器能力。
- **自己尝试 · 本地网页**：给 HTML/CSS/JS 文件、服务启动方式与 DevTools 步骤。
- **自己尝试 · 本地 Node**：给 Node 基线、文件与终端命令。
- **自己尝试 · 本地 React / UI5**：给 package 清单、项目文件、启动/构建步骤。
- **可选页面演示**：站内少量预构建演示，不替代自己做。

验证标签：

| 状态 | 可显示的表述 | 必要记录 |
| --- | --- | --- |
| executed | 已在指定环境运行验证 | 日期、运行时/依赖版本、命令或操作、实际结果 |
| reviewed | 已核对代码与官方资料，请自行尝试 | 核查日期、来源；不写“已测试通过” |
| unverified | 尚未运行验证，请自行尝试 | 说明状态、操作步骤、预期结果；不可声称运行通过 |

同一篇有多个例子时，逐个标注。练习是操作类型，起始代码与参考答案分别记录验证状态。含 TODO 属于有意留空，必须解释要补什么，不能把不完整代码伪装成可直接运行的成品。

## 「自己尝试」模板

```text
自己尝试 · 本地 React
前置：完成 C21–C24；使用本课记录的 Node 和依赖版本。
目标：修复连续更新只加 1 的问题。
文件：src/Counter.jsx；项目启动步骤见本课前置说明。
操作：运行项目 → 点击一次“+3” → 观察屏幕 → 用 DevTools 查看 state。
预期：一次点击增加 3；其他按钮行为不变。
提示：比较读取本次快照和接收待处理状态的两种更新方式。
验收：解释原因，补充回归测试，再查看参考答案。
常见失败：Hooks 在条件内调用、立即执行事件函数、修改对象后未产生新状态。
```

代码旁边说明其位置。命令必须给工作目录；已有锁文件才教 npm ci。不要混淆网站工程、学习者练习工程和 Node 后端。

## Java 迁移的必讲差异

| 已有 Java 经验 | 必须澄清的 JS 行为 |
| --- | --- |
| 静态类型变量 | let/const 的绑定限制与动态值类型；const 不冻结对象 |
| int/long/BigDecimal | Number 的浮点与精度；BigInt 与 Number 不随意混算；价格用整数分示范 |
| equals/hashCode | === 对象身份、Map 对象键身份；不要说内容相同就相等 |
| 对象传参 | 两者均不能简单说“按引用传参”；JS 传的是值，对象引用值的副本会指向同一对象 |
| Java class/this | JS class 基于原型；this 受调用方式影响；箭头函数采用词法 this |
| 数组/集合 | JS Array 动态、可稀疏；越界读取常得到 undefined；sort 默认不是数字排序 |
| Stream/lambda | map/filter/reduce 与函数是值的便利；数组操作会不会突变需要逐个判断 |
| Java 线程/Future | await 暂停当前 async 流程，异步 I/O 与 CPU 并行不同；Node 有系统 I/O/线程池等 |
| Maven/JUnit | npm 的部分职责可类比 Maven；Vitest 是运行器，RTL 是组件测试辅助工具 |
| 可变对象字段 | React state 属于一次渲染快照，不能直接修改并期待画面更新 |
| Java 接口/泛型 | TS 类型会擦除，不提供运行时 JSON 校验；Vite 转译不等于类型检查 |

不要声称 JS 就是“弱化版 Java”，不要把空数组/对象的 truthy、null/undefined、??/|| 等易错点一带而过。

## 代码与调试

- 示例优先短小、可以复制；使用有意义的业务命名。
- 输入、输出、错误情况都有解释；异步日志要说明顺序与环境差异。
- 正常实现与错误示例明确分开，错误例子给复现步骤。
- 调试练习写“观察什么、依据什么判断、怎样验证修复”，不只堆 console.log。
- DevTools 临时修改与修改源文件分开说明；source map 是映射，不能保证所有部署都公开原始源码。
- 测试断言用户可观察结果，纯函数测试覆盖业务边界；不要对每一行实现写同样的镜像测试。
- 示例注释解释原因；不重复一眼能看到的动作。

## D2 与图的比例

只用 D2 绘制教学机制图，保留源码并生成 SVG。大部分课没有图；复杂课 1–2 张，全站先做 8–12 张。

闭包、引用/原型、事件循环、React 状态流、Effect 清理、UI5 体系/绑定、部署流程值得画。单个 if、一次 map、组件 API 清单用代码或表格即可。

每图聚焦一个问题，有短标题、中文可读文字、文字替代；不把长段解释塞进节点。图不能成为理解代码的唯一途径。

## “最新”与来源规则

- 官方规范、项目文档与发布说明优先。历史故事可引用原设计者/标准工作者的历史论文。
- 标明查询日期和实际使用版本；实现时重核安装命令与依赖兼容性。
- 分别说明已发布年度标准、Stage 4、尚未完成提案和运行环境支持。
- 不把某个运行时先支持的能力直接说成所有浏览器已支持。
- 旧教程的 CRA、旧 UI5 React 事件限制等不能直接继承；以当前文档与实际锁版验证为准。
- 组件库用定位与功能比较，不声称没有依据的市场排名。
- 许可证按包/产品说明：例如 MUI Core 与 X Pro/Premium 分别说明。
