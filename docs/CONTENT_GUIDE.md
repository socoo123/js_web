## 1. 读者与语气

- 读者是写过几年 Java 的后端工程师，没系统学过前端。他聪明，没耐心看废话，关心「为什么会这样」。
- 语气像资深同事带你看代码：用「你」，短句，先给结论再讲原因。
- Java 程序员已经会的东西一句话带过，例如 for/if 语法、try/catch 结构、Big O、栈和队列的概念。篇幅留给 **JS 和 Java 行为不同的地方**。
- 类比 Java 时，一句讲相同点，一句讲在哪里失效，不展开成段落。
- 正文是写给学员的，不是写给审阅者的。证明「我很严谨」的内容（核查过程、未覆盖的平台、作者用什么工具跑的）一律不进正文。

## 4. 一个概念节怎么写

固定节奏：**主张**（1–3 句）→ **代码**（最好 ≤ 15 行）→ **输出** → **为什么**（2–4 句）→ **Java 对照**（有就写一句）。

- 每课至少 2 处「先猜输出」：代码前写 `**先猜一猜：**` 加一个问题，输出放在代码之后 [lint ≥ 2]。
- 一段代码只演示一个概念。不要写一个 60 行的片段同时测 8 种行为。
- 输出紧跟代码：短例子用行尾注释 `// → 12`，多行输出用 `text` 代码块。

示范（文字约 200 字，这个密度就对了）：

````md
### `??` 和 `||`：库存为 0 时谁会出错

两者都能写默认值，区别在于什么算「没有值」。

**先猜一猜：** 已售完的商品，下面两行分别打印什么？

```js
const savedStock = 0; // 已售完
console.log(savedStock || 12);
console.log(savedStock ?? 12);
```

```text
12
0
```

`||` 遇到任何 falsy 值（`0`、`""`、`false`、`NaN`、`null`、`undefined`）都换成右边；`??` 只在 `null` 或 `undefined` 时换。库存、价格、开关这类 `0` 和 `false` 有意义的字段，默认值用 `??`。

Java 最接近的写法是 `Objects.requireNonNullElse(stock, 12)`，它同样只处理 null。
````

## 5. 自己尝试、运行环境与验证标注

**自己尝试**：需要学员亲手操作的地方，用 Starlight 提示框，每课至少 1 个 [lint]：

```md
:::tip[自己尝试 · Node]
1. 在 `examples/c06` 目录运行 `node counter.js`。
2. 把 `createCounter()` 调用两次，分别调用各自的 `next()`。

预期：两个计数器互不影响，分别打印 1、2 和 1。
:::
```

环境标签只用这几个：`浏览器 Console`、`本地网页`、`Node`、`本地 React`、`本地 UI5`。

**运行方式**：从 C06 起，纯语言的例子默认用 `node 文件名.js` 运行（Node 24 LTS），浏览器 Console 作为备选；DOM 相关的例子用本地网页。C06 开头用 5 行左右给出安装 Node 的步骤（官方下载、`node --version`），不展开 nvm 等版本管理器。C06 之前的课以浏览器 Console 为主、Node 为备选，写法见 C03。

Chrome 的 Console 允许在不同输入之间重复声明 `let`/`const`，但不允许把前面的 `let x` 再声明成 `const x`。同一课里会被依次粘贴的代码块，顶层变量名不要一处用 `let`、另一处用 `const`。

**验证标注**：要诚实，但记在对的地方。

| 位置 | 写什么 |
| --- | --- |
| 页首信息行 | `示例已运行验证`；或 `部分示例未运行，已在对应位置标注` |
| 例外的代码块前 | `> 未运行验证：原因。请按步骤自己尝试。` 只有没跑过的例子才标 |
| `examples/cNN/README.md` | 环境版本、命令、每个文件的结果，格式见第 12 节 |

没有运行过的例子不能写「已验证」。

正文禁止出现以下内容 [lint]：

- 内部编号，例如 S01、V03、E02、A01、H01、J01。练习用「练习 1」，示例用文件名。
- 带补丁号的版本，例如 `Chrome 155.0.8059.40`、`Node 24.22.0`。正文写「Node 24」「Chrome」即可，精确版本只写进 examples README。
- `操作方式：`、`验证状态：` 这类逐块标签。
- 「作者环境」「作者实际」「调试协议」「临时替换」「不宣称」「不承诺」「不能据此」「推导成」「写成已验证」等写给审阅者的话。
- 「资料与实际验证记录」这类章节，统一改为「延伸阅读」。

## 6. 正面写作，不写防御式免责

规则：

1. 先讲规则本身，例外放在后面，而且只讲会影响本课练习的例外。
2. 一个误区只在最相关的位置讲一次，不在每节重复。
3. 每段最多一个限定条件。需要第二个时，考虑删掉或单独成段。
4. 不写「不要因此推导出……」。如果担心读者误解，直接写出正确的结论。

对照 C01–C05 中的实际段落：

| 原文（不要这样写） | 改写 |
| --- | --- |
| 这节使用固定的、较小的整数分，不从任意小数输入直接乘 100。不要因此推导出 `Number("任意价格文本") * 100` 总是精确，也不要认为结果在安全整数内就自动规定好了税费和折扣的舍入规则。金额扩大、除法分摊、不同币种和后端精确数据需要单独定义单位、范围与舍入方式；本课先把库存项目中的基本表示选对。 | 金额统一用「分」存成整数：`1990` 就是 19.90 元。整数的加、减、乘没有小数误差，只在显示时除以 100。打折、分摊这类需要舍入的计算，要先和业务约定舍入规则。 |
| > 资料核查：2026-10-15。语言规则对照 ECMAScript 2026 固定版本；示例文件已在 Node 24.22.0 与 Chrome 155.0.8059.40 实际执行；手动 Console 路径已核对。各项边界见课尾。 | > 前置：C02 · 运行：浏览器 Console 或 Node 24 · 示例已运行验证 |

## 7. Java 迁移必讲的差异

下表是全课程的重点。每课只讲与本课相关的几行，讲透为止。

| 已有 Java 经验 | 必须讲清的 JS 行为 |
| --- | --- |
| 静态类型变量 | let/const 只限制重新赋值，值的类型是动态的；const 不冻结对象 |
| int/long/BigDecimal | Number 是双精度浮点；BigInt 不能和 Number 混算；金额用整数分 |
| equals/hashCode | `===` 比较对象身份；Map 的对象键按身份匹配，内容相同也是不同的键 |
| 对象传参 | 两种语言都是传值；对象参数传的是引用的副本，改字段会影响原对象，给参数重新赋值不会 |
| class/this | JS class 基于原型；this 由调用方式决定；箭头函数没有自己的 this |
| 数组/集合 | Array 动态、可稀疏；越界读取得到 undefined 而不是异常；sort 默认按字符串排序 |
| Stream/lambda | map/filter/reduce 不改原数组，sort/splice/reverse 会改；函数本身是值 |
| 线程/Future | 单线程事件循环；await 只暂停当前 async 函数，不会开新线程 |
| Maven/JUnit | npm 管依赖和脚本；Vitest 是测试运行器，RTL 是组件测试的辅助库 |
| 可变对象字段 | React state 是某一次渲染的快照，直接修改不会触发更新 |
| 接口/泛型 | TypeScript 的类型在运行时被擦除，不会替你校验 JSON |

## 8. 代码规范

- 库存数据用 PLAN §3.1 的固定样例数据，可以只取子集，但同一个 id 的名称、分类、库存、价格不能改。
- 业务命名用英文（`products`、`stock`、`priceCents`），界面文字和日志可用中文。
- 错误写法和正确写法分成两个代码块。错误写法的第一行注释写 `// 有问题的写法：……`。
- 带 `title="xxx.js"` 的代码块必须与 `examples/cNN/xxx.js` 内容逐字一致。
- 输出固定的 Node 例子要配 `xxx.expected.txt`，由 `npm run examples -- cNN` 自动核对。故意抛错的文件第一行写 `// expect-error: TypeError`。
- 注释只解释原因，不复述代码在做什么。
- 命令要写明工作目录。已有锁文件的项目才教 `npm ci`。

## 9. 常见错误与调试

每课 1–2 个真实 bug，按这个顺序写：

1. **现象**：学员会看到什么（错误信息、错误输出、页面表现）。
2. **工具**：打开哪个面板或运行什么命令，路径写到可以照着点（Sources → 在行号上单击设断点）。
3. **证据**：在那里看到了什么值或请求。
4. **原因**：一两句话。
5. **修复**：改哪一行。
6. **确认**：重复第 1 步，现象消失；C20 起，适合自动化的 bug 补一条 Vitest 回归测试。

不要用「刷新就好了」或「加一句 console.log」当成找到了原因。
