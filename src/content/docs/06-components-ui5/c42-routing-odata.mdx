Product 是类型，Products 是实体集，id 是键，P002 才是一条实体。Edm.String、Edm.Int32 描述标量类型。实验把六商品投影为这五个标量字段；tags 仍留在主应用，没有被编辑丢弃。固定样例的整数分在 Int32 内，真实金额类型按服务契约选择。

桥接命令已从 `data/products.json` 生成 `localService/mockdata/Products.json`，不手抄第二份数据。重新启动 dev 会更新生成物。V2 请求的 `$metadata` 由浏览器 mock 响应，metadata.xml 则是实际要部署的静态资源。

| 请求相对服务根 | 含义 |
| --- | --- |
| `$metadata` | 服务结构、实体集与键 |
| `Products` | 实体集，大小写来自 metadata |
| `Products('P002')` | 字符串键为 P002 的实体 |
| `Products?$filter=stock ge 1 and stock le 5` | 库存 1–5，排除售罄 |

`$orderby=stock desc,id asc` 排序，`$top=2` 限数量，`$skip=1` 跳过一件，`$select` 只取指定字段。范围内顺序为 P006:5、P004:3；跳过第一件再取一件只得到 P004:3。Java Stream 的筛选/排序/limit 是相近的计算，但真实 OData 查询交给服务执行。

## 4. JSONModel 与 ODataModel：相似的绑定，不同的取数方式

JSONModel 的 `/products/3` 指向已在本地的对象。V2 ODataModel 的 `/Products('P004')` 描述服务资源，数据经读取进入缓存；V4 使用另一套 binding/Promise API，不能把 V2 的 read 原样搬去。

**先猜一猜：** getProperty 返回 undefined，就能证明服务没有 P999 吗？不能。它只读已加载缓存，不主动请求。完成下一节后，在读取页 Console 执行：

```js
const model = window.odataProbe.model;
console.log(model.getProperty("/Products('P999')/stock")); // → undefined
model.read("/Products('P002')", {
  success: (product) => console.log(product.id, product.stock), // → P002 0
  error: (error) => console.log("读取失败", error.statusCode),
});
```

read 返回请求句柄，不是数据 Promise；结果在 success/error 中。实体集返回 `data.results`。分页缓存或本页合计不能当成全量统计；本实验的小计 8、3，都不是库存主应用的 52。

### 从 mock 到真实 SAP 服务

真实接入先确认协议、服务根、metadata、认证与权限。401 查会话，403 查权限/请求保护；写入还可能需要 CSRF token、ETag 和后端业务校验。Pages 只提供静态文件，密码和 client secret 不进入前端。UI5 Router 切页面，服务端 Application Router/Destination 连接后端，是不同职责。

## 常见错误与调试

### 搜索后点第一行，详情指向错误商品

**现象**：在 onDetail 中故意把 id 来源改成 `this.byId("products").indexOfItem(event.getSource())`。筛选 P004 后点击，地址出现 0，详情未找到商品。

**工具**：Sources → Inventory.controller.js，在 navTo 行设断点，再筛选并点击。

**证据**：可见索引是 0，而事件源 context 的路径是 `/products/3`，id 为 P004。

**原因**：把界面投影位置当成商品身份。

**修复**：恢复 `getBindingContext("inventory").getProperty("id")`，详情继续按 id 查当前数组。

**确认**：同样操作得到 P004 hash，复制并刷新仍显示库存 3；未知 P999 有明确反馈。`npm run lab -- check C42` 同时检查详情与有限查询。若读取页报 404，先比对 Products 大小写、rootUri 与 serviceUrl，不把 JSON 数组名 products 当实体集名。

## 小结

- route 匹配 hash，target 放置 View，initialize 开始处理地址。
- id 是身份，context 是当前模型位置；刷新时先等数据。
- OData metadata 描述实体、集合、键；查询返回的子集有自己的统计口径。
- JSONModel、V2 与 V4 ODataModel 的数据入口与 API 不同。
