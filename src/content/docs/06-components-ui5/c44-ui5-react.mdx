## 这一课解决什么问题

同样编辑 P004，原生组件、Ant Design 和 OpenUI5 都遵守一条业务规则：草稿可以取消，保存才改正式库存。本课把这条规则接到 UI5 React，只做筛选列表与库存编辑，不重写完整 CRUD。

最重要的连接是：输入框读出文本，公共 core 校验，原生 form 产生 submit，repository 保存。点击保存、在库存框按 Enter、聚焦保存按钮后按 Enter，都必须只确认一次。

接 C43 自己的完成态，仍在 `inventory/`。C36 的 `src/react/` 主应用和 `src/core/`、`src/services/` 全部保留；本课新增的适配器与另外三种界面并列。下面先完成两个文件再启动服务，避免编辑到一半时导入尚不存在的文件。

## Java 程序员先看这里

包装库像 adapter：把调用入口换成 React 组件与回调，底层仍是真正的自定义元素。它不把 UI5 事件变成 Ant Design 的参数，也不会接管业务校验。Java 布局容器和提交动作各有职责；这里大写 `Form` 排版，小写 `form` 提交，名称相似但不是同一组件。

## 5. L4 换的是界面，交付边界保持不变

四种适配器共用 core，React 适配器共用 C32 的 repository。经典 UI5 用 JSONModel.setProperty 通知绑定，React 包装层用 props 与 state 重新渲染；把 `inventory>/draft/stock` 塞进 Input.value，只会显示那串文本，不会建立 XML 绑定。

已有 `Settings.jsx` 的两个下拉框分别调用 `await setTheme("sap_horizon_dark")` 与 `await setLanguage("en")`。它等待资源配置完成后再启用控件；页面 CSS 使用 SAP 主题变量，所以外部页面与 Shadow DOM 控件能一起变深。组件语言改变内置文案，业务标题仍由应用提供。

## 常见错误与调试

<a id="保存按钮可以按却没有进入提交函数"></a>

**现象**：按钮能按，但扩展坞一直是 3，总库存一直是 52。故意把 ProductEditor 的外层原生 form 换成布局 Form，会得到这个错误结构：

```jsx
// 有问题的写法：布局容器不能替代原生提交容器
<Form onSubmit={submit}>
  <FormItem labelContent={<Label>库存</Label>}>
    <Input value={draft.stock} />
  </FormItem>
  <Button type="Submit">保存库存</Button>
</Form>
```

**工具**：Sources 打开 `adapters/ui5-react/ProductEditor.jsx`，在 submit 第一行行号上单击设断点；点击保存，再到 Elements 查看 ui5-input 祖先。

**证据**：断点未命中，HTML form 不存在；type 为 Submit 的 UI5 按钮没有原生表单可提交。**原因**：大写 Form 不提供原生提交 API，写一个 onSubmit prop 不会凭空产生事件。

**修复**：恢复外层 `<form ... onSubmit={submit}>` 和对应结束标签，内部 Form 仍然排版。**确认**：用同样的 8，点击和两种 Enter 路径各从固定数据重放，断点命中一次、确认次数为 1、总库存为 57；空白仍不能保存。

工作区 `npm run lab -- check C44` 检查当前实际源码，浏览器回归覆盖提交连接。只有 parseDraft 的纯函数测试通过，还不能证明真实按钮、Shadow DOM 和表单接好了。

## 小结

- 包装组件改变 React 调用入口，不改变底层元素的事件与资源契约。
- 草稿保留文本，core 校验转换，repository 是唯一正式写入口。
- Form 排版，form 提交；按钮与 Enter 只汇合到一个 submit。
- 全量汇总和筛选列表的输入范围要分清，更新始终按 id。
