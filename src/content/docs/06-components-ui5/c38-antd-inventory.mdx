## Java 程序员先看这里

Java 的编辑 DTO 与实体分离经验仍然适用：Form 字符串草稿不是正式商品。但 `initialValues` 是表单实例的初始值，**不是每次 props 变化都会执行的 Bean 赋值**。本课用“关闭后卸载整次编辑会话”得到新实例；只隐藏弹窗则不会自动丢弃旧草稿。

## 1. 接入组件库，先保留业务模块

先读 App 已有的三段接线，不修改它们：

```jsx
const repository = createInventoryRepository({ storage: null, seed });
// App 内，inventoryRepository 默认使用上面的独立实例
const list = useQuery({ queryKey: ["antd", "products"], queryFn: () => inventoryRepository.list() });
const saveMutation = useMutation({
  mutationFn: (product) => inventoryRepository.save(product),
  onSuccess: () => cache.invalidateQueries({ queryKey: ["antd", "products"] }),
});
```

结果：list 读六商品，mutation 保存后刷新列表缓存。没有第二份可写 `products` state；`list.data` 是缓存结果，`selectProducts` 派生显示行，`summarize(products)` 始终统计全部商品。App 还提供读取中、失败重试和搜索空态的容器。

`main.jsx` 已从 `react-dom/client` 创建入口，并用 QueryClientProvider 包住 App。App 从 `../../src/services/inventory-repository.js` 导入工厂，从 `../../src/core/inventory.js` 导入筛选和汇总；相对路径从 adapter 回到同一个公共模块。Java 里换一个界面适配器，也不应顺手复制服务和校验类。

## 2. Table：字段用于显示，记录用于操作

**先猜一猜：** 库存升序后首行 P002 的 `index` 是 0，编辑应传 P002 还是原数组第 0 项？把 `ProductTable.jsx` **整文件替换**为：

```jsx
import React from "react";
import { Button, Table } from "antd";
import { formatPriceCents } from "../../src/core/inventory.js";

export default function ProductTable({ products, onEdit }) {
  const columns = [
    { title: "编号", dataIndex: "id", width: 90 },
    { title: "商品", dataIndex: "name", width: 190 },
    { title: "分类", dataIndex: "category", width: 90 },
    { title: "库存", dataIndex: "stock", width: 90, sorter: (a, b) => a.stock - b.stock },
    { title: "价格（元）", dataIndex: "priceCents", width: 120,
      sorter: (a, b) => a.priceCents - b.priceCents, render: formatPriceCents },
    { title: "标签", dataIndex: "tags", width: 130, render: (tags) => tags.join("、") || "—" },
    { title: "操作", key: "edit", width: 100, render: (_value, record, index) =>
      <Button aria-label={`编辑 ${record.id}`} onClick={(event) => onEdit({ id: record.id, index }, event.currentTarget)}>编辑</Button> },
  ];
  return <div className="antd-table"><Table rowKey="id" dataSource={products} columns={columns}
    pagination={false} scroll={{ x: 810 }} locale={{ emptyText: "没有符合条件的商品" }} /></div>;
}
```

结果：六行使用 id 作 key，库存和价格按数字排序，价格才在显示时转成元。`render` 的第二个参数 record 是当前商品，第三个是显示位置。事件同时携带位置便于观察，选择器只使用 id；配置 rowKey 和正确传事件是两件都要做的事。

在 App 中**只替换占位的 openEditor 函数**：

```jsx
function openEditor(row, button) {
  const product = selectProduct(products, row);
  if (!product) return;
  trigger.current = button;
  setEditor({ product: structuredClone(product), open: true });
}
```

`selectProduct` 已从 `./select-product.js` 导入，正是上一课按 id 的函数。App 已把 `openEditor` 作为 ProductTable 的 onEdit 传入。复制商品得到隔离编辑会话，trigger 只记焦点目标；排序后打开鼠标仍读到 0。Java 排序视图同样需要稳定主键，而不是把两个数组的下标混用。

## 3. Form：只存草稿，提交时跨过输入边界

Form 管草稿与字段错误，公共 `parseStock` 管业务规则。**先猜一猜：** P004 输入文本 `"8"`，尚未保存时正式库存与总库存是多少？仍是 3 和 52；输入 `""` 不能通过规则，`"0"` 可以。

<a id="规则复用已有函数"></a>

把 `ProductEditor.jsx` 整文件替换：先放下面的导入和函数前半段，**函数暂不闭合**，随后接第 4 节的 return 与结尾：

```jsx
import React, { useRef, useState } from "react";
import { Alert, Form, Input, Modal } from "antd";
import { parseStock } from "../../src/core/inventory.js";
import { cycleDialogFocus } from "./cycle-dialog-focus.js";

export default function ProductEditor({ product, open, onSave, onCancel, afterClose }) {
  const [form] = Form.useForm();
  const [pending, setPending] = useState(false);
  const [error, setError] = useState("");
  const input = useRef(null);
  const saving = useRef(false);
  const stockRule = { async validator(_rule, value) { parseStock(value); } };

  async function finish({ stock }) {
    if (saving.current) return;
    saving.current = true;
    setPending(true); setError("");
    try { await onSave({ ...product, stock: parseStock(stock) }); }
    catch (caught) { setError(caught.message); }
    finally { saving.current = false; setPending(false); }
  }
```

结果：输入空白/负数时共享解析函数抛错，async validator 返回拒绝的 Promise，Form 显示该错误；通过后 `finish` 得到字符串，再转换为数字。`{ ...product, stock }` 只替换库存，名称、分类、整数分价格、tags 不丢失。repository 仍会在保存前校验整件商品。

pending 驱动界面，saving ref 立即挡住连续提交；失败显示错误并保留草稿。这里没有把商品修改塞进 Effect，也没有复制校验范围。像 Java DTO 转成业务值一样，转换发生在正式提交边界。

<a id="字段用-name-进入-form"></a>

下一段的 `Form.Item name="stock"` 会给 Input 注入 value/onChange；无需再写一份库存 useState。Input 保留字符串，`inputMode="numeric"` 只提示键盘类型。错误通过 Form 关联到字段，`scrollToFirstError` 负责把焦点送到第一个失败字段。

## 4. Modal：把关闭、销毁和提交分开

在刚才的 `finish` 后**继续追加以下代码**，最后一行闭合组件函数：

```jsx
  return <Modal title={`编辑 ${product.id} ${product.name}`} open={open}
    onCancel={() => { if (!saving.current) onCancel(); }} onOk={() => form.submit()}
    okText="保存" cancelText="取消" confirmLoading={pending}
    okButtonProps={{ "aria-label": "保存" }} cancelButtonProps={{ "aria-label": "取消", disabled: pending }}
    mask={{ closable: false }} closable={!pending} keyboard={!pending} destroyOnHidden
    focusable={{ trap: true, focusTriggerAfterClose: true }} afterClose={afterClose}
    modalRender={(node) => <div onKeyDown={cycleDialogFocus}>{node}</div>}
    afterOpenChange={(visible) => { if (visible) input.current?.focus(); }}>
    <p>取消或按 Esc 丢弃草稿。只编辑库存，其他字段保持原值。</p>
    {error && <Alert type="error" title={error} />}
    <Form form={form} name="antd-stock" layout="vertical" preserve={false}
      initialValues={{ stock: String(product.stock) }} onFinish={finish}
      disabled={pending} scrollToFirstError={{ focus: true }}>
      <Form.Item name="stock" label="库存数量" rules={[stockRule]}>
        <Input ref={input} inputMode="numeric" />
      </Form.Item>
      <button type="submit" hidden>保存库存</button>
    </Form>
  </Modal>;
}
```

结果：Enter 在原生 form 中提交，Modal 确认按钮经 `form.submit()` 走同一条校验；隐藏 submit 只为原生表单提供默认提交入口，不额外监听 Enter。校验失败不关闭，失败重试仍用原草稿。

最后在 App 中**替换占位的 save 函数**：

```jsx
async function save(product) {
  await saveMutation.mutateAsync(product);
  closeEditor();
}
```

App 已有条件渲染和关闭回调，保留它们：

```jsx
function closeEditor() { setEditor((current) => current && { ...current, open: false }); }
function afterClose() { setEditor(null); trigger.current?.focus(); }
// App 返回的 main 内已经连接，不要再插入第二份：
{editor && <ProductEditor product={editor.product} open={editor.open}
  onSave={save} onCancel={closeEditor} afterClose={afterClose} />}
```

这形成完整生命周期：open=false 先做关闭动画；`destroyOnHidden` 卸载 Modal 内容；`preserve={false}` 不留字段值；afterClose 把 editor 置空，**创建 Form 实例的 ProductEditor 也卸载**。下次从商品新建会话，所以取消 P001 的 8 后打开 P002 得到 0。若选择让同一实例一直存在，需主动 `setFieldsValue` 并处理重置；本课不用那条设计。

<a id="焦点要和数据一起验收"></a>

`afterOpenChange` 在打开动画后聚焦字段，`focusable.trap` 管模态焦点，afterClose 回到实际按钮。入口已提供 `cycle-dialog-focus.js`：它从 modalRender 的包装层找可见可用控件，在首尾拦截 Tab/Shift+Tab 并转向另一端，避免焦点去往地址栏。上面的导入和 modalRender 把这个辅助机制连上。确认/取消按钮显式提供 aria-label，避免中文双字排版改变可访问名称。

关闭、卸载、保存不是同一事件；类比 Java 编辑缓冲区可以帮助理解草稿，但浏览器动画和焦点需要实际操作。

## 5. 主题贯穿弹窗，功能范围按具体包判断

App 已用 ConfigProvider 包住表格和编辑器，`dark` 切换 `theme.darkAlgorithm` 与 `defaultAlgorithm`。声明式 Modal 虽挂在 body，仍能接收 React Context；只写局部 DOM 选择器则未必能选中它。点击“切换深色”后**重新打开弹窗**，确认文字、输入、错误和背景都变化。

## 常见错误与调试

### 打开鼠标，库存却是刚才键盘的草稿

**现象**：在当前 App 把 `afterClose` 改成只返焦点、不调用 `setEditor(null)`；在当前 ProductEditor 移除 `destroyOnHidden`，并将 `preserve={false}` 改成 `preserve={true}`。编辑 P001，输入 8 后 Esc，再打开 P002：标题是鼠标，库存却仍为 8。

**工具**：React DevTools → Components → ProductEditor 查看 product；Elements 选中库存 input，Console 读取 `$0.value`；Sources 在 `finish` 内设断点。

**证据**：`product.id=P002`、`product.stock=0`，Form 的 initialValues.stock 是 `"0"`，DOM value 却为 `"8"`。**原因**：表单实例存活，initialValues 不会覆盖已修改的草稿。**修复**：恢复第 4 节的销毁、preserve 和 afterClose 三处接线。**确认**：P001 改 8 取消→P002 得 0；取消→再开 P001 得 12；按下列命令运行当前源码的回归：

```sh
node tools/antd-browser.mjs --case=lifecycle
npm run lab -- check C38
```

第一条只检查连续开关，错误版本应红，修复后绿；完整检查还覆盖 P004、非法输入、排序与静态子路径。它不会注入故障或替你修改源码。
