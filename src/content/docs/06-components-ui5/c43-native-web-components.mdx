## Java 程序员先看这里

Java 的 listener 经验可以沿用：控件发事件，监听器调用业务。但这里的控件是浏览器 DOM 元素，需要先注册标签。HTML attribute 是文本标记，JS property 才是对象上的值；布尔 setter 对应 `save.disabled = false`，不是字符串 `"false"`。

经典 UI5 的 Component、XML View、JSONModel 不参与这个 adapter。自定义元素提供输入和外观，应用负责草稿、校验与保存。

## 2. 属性传值，事件通知：业务计算仍在外面

### attribute 是标记文本，property 是 JS 值

**先猜一猜：** 输入文本 `"0"` 应该变成什么？`disabled="false"` 又会启用按钮吗？前者交给 `parseStock` 得到数字 0；后者仍禁用，因为这个布尔 attribute 存在就是真。

完成编辑器后，在页面 Console 可以观察并恢复按钮：

```js
const saveButton = document.querySelector("#save");
saveButton.setAttribute("disabled", "false");
console.log(saveButton.hasAttribute("disabled"), saveButton.disabled); // → true true
saveButton.removeAttribute("disabled");
saveButton.disabled = false;
console.log(saveButton.disabled, typeof saveButton.disabled); // → false boolean
```

动态开关直接给 property 赋布尔值。输入的 `value` 则一直是字符串；即使看起来像数字，也要在业务入口转换。这里编辑的是库存总数，合法 0 与“补货数量必须大于 0”是不同规则。

## 3. Shadow DOM 管内部实现，slot 接收页面内容

Input 宿主是 `ui5-input`，内部原生 input 在 shadow tree；你写的 span 则属于页面的 light DOM。打开编辑后在 Console 运行：

```js
const stockElement = document.querySelector("#edit-stock");
console.log(stockElement.querySelector("input")); // → null
console.log(Boolean(stockElement.shadowRoot.querySelector("input"))); // → true
console.log(stockElement.querySelector("#value-message").parentElement === stockElement); // → true
```

slot 是插入页面内容的位置，不是把节点的所有权交给组件。`slot="valueStateMessage"` 精确对应 Input 的命名槽，Negative 状态时可显示你提供的错误文案；保存按钮文字使用默认槽。打开 Elements → ui5-input → `#shadow-root (open)`，可以看到内部树与分配到槽的内容。

样式也有树边界：

```css
ui5-input { width: 100%; }
ui5-input input { color: red; }
ui5-input::part(input) { letter-spacing: 2px; }
```

第一行改变宿主；第二行进不了 shadow tree；第三行通过公开 part 改内部字间距。配色用主题接口，局部定制先查 CSS Parts。像 Java 类的公开接口一样，业务代码不依赖控件内部实现；open shadow root 便于检查，不是安全隔离。

## 5. React 19 可以直接使用这些元素

React 19 支持自定义元素的 property 和自定义事件。直接使用 `ui5-input` 时，事件 prop 是 `on` 加事件原名，即 `onui5-input`；布尔 disabled 传布尔值。元素应先注册，React 才能识别它暴露的 property。

React 包装库提供另一套适合 React 的组件名与事件接口，而不是给经典 OpenUI5 套一层 JSX。下一课比较包装 API，并建立原生 form 的提交链；本课的小编辑区保留为独立对照。

## 常见错误与调试

### 按钮始终灰着，明明写了 false

> 未运行验证：下文 DevTools 面板的手动点选与断点尚未逐项运行。请按步骤自己尝试。

在 `editor.js` 的 validate 成功分支，故意把 `save.disabled = busy` 改成：

```js
// 有问题的写法：把布尔开关写成字符串 attribute
save.setAttribute("disabled", String(busy));
```

1. **现象**：打开 P004，输入合法的 8，保存却一直灰着。
2. **工具**：Elements 选中 `#save`；Console 读取 `$0.getAttribute("disabled")`、`$0.disabled`。Sources 在这行设断点。
3. **证据**：busy 为 false，但 attribute 值是字符串 false，property 为 true。
4. **原因**：attribute 存在即禁用，字符串内容没有改变布尔规则。
5. **修复**：恢复 `save.disabled = busy`；不需要删除合法的输入校验。
6. **确认**：重复输入，保存恢复可用，P004 保存成 8，总库存 57。运行 `npm run lab -- check C43`；浏览器回归会检查实际按钮可用性与保存结果，错误写法应先失败，修复后通过。

<a id="输入框变了预览一直停在-15"></a>

若输入已是 8，反馈仍显示草稿 3，先在 `ui5-input` 回调设断点。回调不命中时对照事件名，不能把它拼成 `ui5Input`；命中后才继续检查值。这是接线错误，不是缓存或样式问题。

## 小结

- 自定义标签先注册，界面仍由 DOM 事件和应用 JS 连接。
- attribute 是文本配置，property 是 JS 值；布尔 attribute 存在即真。
- Input.value 是字符串，真实事件触发共享校验，保存才调用 repository。
- Shadow DOM 封装内部树，slot 接收页面内容，公开 parts 提供局部样式入口。
- 主题、翻译与本地字体都属于静态产物，React 19 也可以直接使用这些元素。
