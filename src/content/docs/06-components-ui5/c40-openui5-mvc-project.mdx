## Java 程序员先看这里

命名空间类似包名，模块资源路径类似类路径；但加载、XML 解析、控件事件都发生在浏览器。npm 安装 Node 工具，UI5 CLI 提供框架资源，Component 负责应用初始化。不要把这三个职责当成一个运行时。

本课文件的位置是：

```text
adapters/openui5/
  ui5.yaml                         Node 工具的框架/库配置
  webapp/index.html                浏览器入口
  webapp/Component.js              初始化应用与 ui 模型

  webapp/controller/Inventory.controller.js  你改：事件
```

`ui5.yaml` 使用 OpenUI5 1 系列、`sap.ui.core`、`sap.m` 与 Horizon 主题。`specVersion` 描述 YAML 格式；`framework.version` 固定框架，和 CLI 4 的工具版本分开。Java 构建工具和运行库也各有版本。

## 2. bootstrap：从 HTML 进入应用组件

先读已提供的 `index.html`，无需替换。关键连接是：

```html
<script id="sap-ui-bootstrap" src="resources/sap-ui-core.js"
  data-sap-ui-async="true" data-sap-ui-theme="sap_horizon"
  data-sap-ui-resource-roots='{"course.inventory":"./"}'
  data-sap-ui-on-init="module:sap/ui/core/ComponentSupport"></script>
<main data-sap-ui-component data-name="course.inventory"
  data-id="container" data-settings='{"id":"inventory"}'></main>
```

核心启动后，ComponentSupport 创建 `course.inventory.Component`。资源映射把 `course/inventory/Component.js` 解析到当前目录的 `Component.js`。点号类名、斜杠模块 ID、实际文件名要互相对应。

**先猜一猜：** 把静态产物放在 `/js_web/demos/inventory-openui5/`，相对的核心路径会请求哪里？

```js
const entry = "https://example.com/js_web/demos/inventory-openui5/index.html";
console.log(new URL("resources/sap-ui-core.js", entry).pathname);
// → /js_web/demos/inventory-openui5/resources/sap-ui-core.js
```

开头没有 `/` 的相对路径保留应用子目录；`/resources/` 会跳到域名根。浏览器依 URL 找模块，不能依 Java 的磁盘 classpath 猜路径。

## 3. Component 与 manifest：应用初始化和声明配置

### manifest 写“需要什么”，Component 写“初始化时做什么”

已有 Component 先调用父类 init，然后创建名为 `ui` 的 JSONModel，放提示与语言。它声明 `manifest: "json"`，因此 UI5 读取同目录 manifest；异步内容接口让根 View 异步创建。

在 `manifest.json` 的 `sap.ui5.models` 对象内，**保留 i18n 项**，在它前面新增 inventory 项，注意逗号：

```json
"inventory": {
  "type": "sap.ui.model.json.JSONModel",
  "uri": "model/products.json"
},
```

这是插入对象成员，不是整份 JSON。已有 `rootView.viewName` 为 `course.inventory.view.Inventory`，对应 `view/Inventory.view.xml`。启动桥生成的数据外层是 `{"products":[...]}`，所以数组路径是 `/products`。

manifest 由浏览器 UI5 消费；YAML 由 Node CLI 消费。manifest 的 `dependencies.libs` 声明运行库，YAML 让开发服务与构建实际提供库资源。`minUI5Version` 是最低要求，不负责下载版本。

Java 的接口复用经验适用于共享纯函数；UI5 loader 与 ESM 则是不同的模块加载机制，不能在 define 回调里粘顶层 import。

## 常见错误与调试

### 模块名拼错，页面无法启动

**现象**：故意把 Controller 依赖中的 `course/inventory/model/rules` 改为末尾多一个 s 的 `ruless`，开发服务刷新后页面不再正常创建。

**工具**：DevTools → Network 勾选 Disable cache，过滤 ruless 并刷新；Console 展开首个模块加载错误。

**证据**：请求实际应用子路径下的 `model/ruless.js`，响应 404；真实文件是 rules.js，Controller 工厂还没成功运行。

**原因**：资源映射只替换命名空间前缀，不能修正模块名拼写。

**修复**：恢复 `course/inventory/model/rules`，模块 ID 不加 `.js`，文件保留该扩展名。

**确认**：刷新后六件商品出现，P002 显示 0，统计按钮得到 52。再运行 `npm run lab -- check C40`。若只有字段为空，比较 `stock` 和 `Stock`，而不是继续改模块地址。

## 小结

- bootstrap、Component、manifest、View、Controller 连成一条启动链。
- 模型名选数据来源，绝对路径选根数组，相对路径读当前行。
- 共享 core 通过构建桥适配模块格式，不重写业务层。
- 静态应用资源保持相对路径，开发服务成功不能代替子路径构建检查。
