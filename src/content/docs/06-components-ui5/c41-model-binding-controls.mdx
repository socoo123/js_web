## 1. 模型名与绑定路径决定读哪个值

`inventory` 是商品模型，`ui` 是筛选与汇总状态，`draft` 是本次编辑草稿。`{inventory>/products}` 从模型根读取数组；行内 `{inventory>stock}` 没有 `/`，相对于这一行的 binding context 读取。

**先猜一猜：** 筛选 P004 只剩一行，它的 binding context 是 `/products/0` 还是 `/products/3`？

答案是 `/products/3`。筛选改变绑定的可见结果，没有重排原始数组。这个路径属于模型内的数据位置，商品 id P004 才是跨界面与路由的业务身份。

## 4. 校验后保存，formatter 只显示

Java/UI5 对照卡右侧的 `onSave` 先执行 `rules.parseDraft`。名称、库存、元价格都使用共享规则：空白库存无效，0 合法，价格最多两位小数并保存为整数分。字段出错时写入 draft.errors，保持弹窗并聚焦错误字段；成功才调用 `inventory.setProperty`。

`formatter.money` 来自起点提供的只读显示工具。它把整数分转成元文本，不负责反向解析表单。输入转换由 core 负责，显示 formatter 不能成为另一套校验。

## 常见错误与调试

### 筛选后保存错了商品

**现象**：筛选 P004 后编辑可见第一行，保存 8，P004 仍是 3，P001 却变了。

**工具**：Sources 找到当前 Controller，在 onEdit 的 `this._editPath = context.getPath()` 设断点。输入 P004 并搜索，点编辑；在暂停的 Console 分别读取 `context.getPath()`、`context.getProperty("id")`。

**证据**：可见只有一行，context 却给出 `/products/3` 与 P004。若保存路径被写死为 `/products/0`，Model 的第一件会变为 8。表格可见位置不能代替源路径。

**原因**：把投影中的索引误当成原数组索引。

**修复**：保存 context 给出的编辑路径。草稿使用独立 Model，提交通过 setProperty；直接改 `getData()` 返回对象的字段并不会自动通知相关绑定。

**确认**：重新加载固定数据，筛选 P004，改 8 后取消，重开仍是 3；再改 8 保存，P004 与可见汇总为 8，清空筛选后 P001 仍是 12。空白库存保存时弹窗保持打开。
