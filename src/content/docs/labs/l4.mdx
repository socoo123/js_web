## 本 Lab 的任务与规则

在本发行版的工作区，从 C36 的自己的代码继续，依次完成 C37–C44。新增的四个界面并列，不把库一层层套起来，也不各写一遍完整 CRUD。正常学习持续改同一个目录，不每天换快照。

[字段和操作规则](/js_web/labs/rules/)保持一致，本阶段完成四件事：

<LabPoints>

1. **四种界面各完成一次共同场景**

   筛选 P004，填 8 后取消仍为 3，再次编辑保存为 8；全量总库存由 52 变成 57，P001 保持 12。

2. **校验与键盘操作一致**

   空白和负库存拒绝、0 合法；能用键盘打开、输入、取消和保存，每次操作只提交一次。

3. **保留业务字段**

   只改库存时，名称、分类、价格和标签仍保留；筛选、排序后继续按商品编号定位。

4. **OpenUI5 加入详情与查询**

   P004 详情支持刷新与返回，未知编号有提示；能在 Network 看到有限 OData V2 mock 的读取、过滤、排序和分页请求。

</LabPoints>

共享规则始终来自 `src/core/`；React 适配器复用 `src/services/inventory-repository.js`。不复制四份业务校验器。OpenUI5 的构建桥负责模块边界，不负责发明另一套字段规则。

## 起点、切换与暂停

<details id="从阶段-a-的旧发行版继续">
<summary>从阶段 A 的旧发行版继续：一次升级</summary>

旧目录完整保留。工具与锁不会随课程网页更新，阶段 A 的工程需要做一次升级：

1. 下载 <WorkspaceDownload checkpoint="C00" label="本发行版的 C00 骨架" />，解压到新的空目录，例如 `inventory-components/`。
2. 保留新版的 `tools/`、依赖清单与锁、固定 `data/` 和 `adapters/` 机械外壳。迁入自己完成的 `src/`、`notes/`、`tests/` 与 `vite.config.js`；把自己新增的 package.json scripts（如 report/test）逐项合并进新清单，已有 adapter 改动也先比较再合并。不要用旧依赖清单覆盖新版，node_modules 与 .lab 留在旧目录。
3. 在新目录执行一次 `npm ci`，接着 `npm run lab -- start C37`。以后沿用这个工作区，四个适配器外壳不会靠后续 step 自动补进自己的工程。

新版 C00 的 adapter 外壳只提供入口、资源、布局与占位页面。列表、草稿、事件取值和保存仍由对应课程完成，**不包含 C44 表单答案**。

如果 React 前置尚未完成，需要补课或对照，再将 <WorkspaceDownload checkpoint="C36" label="本发行版的 C36 起点包" />解压到另一新目录，执行 `npm ci` 后从 C37 开始。也可在本版工作区运行 `npm run lab -- restore C36 ../inventory-components`；非空目录会被拒绝。安装与下载校验见[工作区入口](/js_web/labs/)。

</details>

<details id="切换检查与暂停">
<summary>切换、检查与暂停</summary>

始终在 `inventory/` 执行 `npm run lab -- start Cnn`、`npm run lab -- dev` 和 `npm run lab -- check Cnn`。只有切换界面时才 Ctrl+C 停止旧服务并重启，不需要同时开四个端口。

- 在 `notes/next.md` 留当前课、改动文件、观察结果、故障证据和下一件事；网站阅读标记与本地检查结果分开记录。
- `npm run lab -- compare C44` 只读比较；恢复 C44 时只向新目录写入。保留自己的未保存草稿与个人快照。

</details>

<details id="完成后去哪里">
<summary>完成后去哪里：进入 L5</summary>

从自己的 C44 继续 [L5](/js_web/labs/l5/)，回到这里保留的 `src/react/` 主应用做全链路排错和静态交付；`start C45` 选择 React 主入口，四个 adapter 保留。UI5 React 不是后续所有课程的强制入口。

需要恢复时，将 <WorkspaceDownload checkpoint="C44" label="C44 完成参考解" />另存到新目录。当前 Lab 的应用在本地构建和预览；课程网站与学习包由各自入口访问。

</details>
