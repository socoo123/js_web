## 从哪里开始

继续你在 L2 完成的 `inventory/`；不用再新建 React 工程。需要补课时，下载 <WorkspaceDownload checkpoint="C20" label="本发行版的 C20 起点包" />，解压到**新的空目录**，在其中执行一次 `npm ci`，然后 `npm run lab -- start C21`、`npm run lab -- dev`。

C20 只包含前一阶段的原生库存与规则，React 组件由你从 C21 开始加入。已有工程也可用 `npm run lab -- restore C20 ../inventory-react` 恢复到新目录；非空目录会被拒绝，不覆盖自己的源码。安装、下载校验与恢复说明见[工作区入口](/js_web/labs/)。

如果 L2 工程来自较早发行版，先按[升级步骤](/js_web/labs/#从较早发行版继续)迁移自己的源码到本版新目录，再继续 C21；旧包的工具和锁不会随网页自动更新。

## 在同一个应用里推进

| 学习段 | 你增加的能力 | 看得到的结果 |
| --- | --- | --- |
| C21–C24 | JSX、props、状态、列表身份与派生值 | 六件商品；P001 连续 +3 为 15，延迟 +3 中再 +1 最终 16；排序不串备注 |
| C25–C28 | 校验、草稿、reducer/Context、ref | 空白拒绝、0 合法；P001 取消后 P002 仍为 0；定时任务可取消、焦点正确 |
| C29–C32 | Effect、竞态、Hook/hash 路由、Query | 一次快捷键一次动作；慢旧请求不覆盖新选择；P004 刷新可直达；缓存按 id 隔离 |
| C33–C36 | Action、性能/加载边界、测试、复盘 | pending 防重复；失败回滚预览并留草稿；统计不旧；三故障有证据与重放 |

数据归属在 C32 明确迁移：repository 管商品和持久化，Query 管缓存，组件管筛选界面与编辑草稿。列表、详情、汇总不能各维护一份可写商品。

## 收尾：一次可观察的业务交付

在独立固定数据中按 [C36](/js_web/05-react/c36-react-project-debugging/) 完成：

1. 初始 6 种、52 件、2634800 分；新建 P007 为“随身转接头 / 配件 / 3 件 / 0.29 元”，结果为 7 种、55 件、2634887 分，新增详情与刷新可用。
2. 从另一份初始数据编辑 P004：草稿 8 后取消仍 3；保存后只有它为 8，总库存 57；名称、分类、金额、tags 保留。
3. 空白和负库存拒绝，0 可保存；提交中按钮禁用；失败时正式值不变、草稿保留，重试后成功。
4. P004 筛选→详情→刷新→返回保留条件；坏 JSON / 非法字段不覆盖好数据，损坏主记录可从明确的有效备份恢复。
5. `npm run lab -- check C36` 通过，`notes/react-review.md` 留下旧统计、缓存身份、存储边界的证据、修复与重放。

这里包含 RTL 行为测试与一条 `/js_web/demos/inventory/` 严格静态浏览器冒烟。学习包与课程网页是静态发布；应用生产构建按课内步骤在本地检查。

## 暂停与继续

在 `notes/next.md` 写当前课、已改文件、观察结果、下一步。导出的是已保存商品，未提交草稿要另存。`start` 不安装答案，`compare` 只读；网页完成标记与你的本地检查分别管理。

完成后直接从自己的 C36 继续 [L4](/js_web/labs/l4/)。需要对照时再用 <WorkspaceDownload checkpoint="C36" label="本发行版的 C36 完成参考解" />另存到新目录，不要覆盖现有工程。
