## 1. 盒模型决定实际占用的空间

每个元素都是一个盒子：内容区、内边距 padding、边框 border，外面还有外边距 margin。width 量的是哪一层，由 box-sizing 决定。

<Predict question="这张卡片在页面上实际占多宽？把 box-sizing 换成 border-box 呢？">

```css
.card {
  box-sizing: content-box;
  width: 300px;
  padding: 0 16px;
  border: 1px solid;
}
```

<div slot="answer">

```text
content-box：外框 334px = 300 + 16 × 2 + 1 × 2
border-box：外框 300px，内容区缩成 266px
```

content-box 的 width 只量内容区，padding 和 border 另加。border-box 把它们算进 width，内容区跟着变窄。

</div>
</Predict>

border-box 让 width 就等于外框，排版时不用心算，所以本课样式的第一行把所有元素统一成 border-box。margin 始终在外框之外。

`$0` 是 Elements 面板当前选中的元素。360px 减去 main 两侧各 16px 的 padding，卡片外框正好 328px；Computed 的盒模型图里，内容区是 294px。

main 的 padding 给窄屏留边，max-width 限制大屏上的阅读宽度。手机浏览器要有 viewport meta 才按真实宽度排版，本课页面的 HTML 已经写好。

**记住：** 先看 box-sizing 再算宽度：border-box 下 width 就是外框。

**Java 对照：** Java 布局管理器也按尺寸预算分配空间；CSS 还要考虑内容自身的最小尺寸和层叠规则。

## 2. Flex 排工具栏，Grid 排卡片

Flex 沿一条主轴排一行控件，放不下就换行。Grid 先声明列轨道（网格里的一列），再把卡片依次放进去。

```css
#filters { display: flex; flex-wrap: wrap; gap: .6rem; align-items: end; }
#filters label { display: flex; flex-direction: column; min-width: 0; }
#list { display: grid; grid-template-columns: minmax(0, 1fr); gap: 1rem; }
```

<Effect kind="page" preview="c15/narrow" />

`flex-wrap` 让放不下的控件换到下一行。gap 管间距，align-items 管交叉轴（与主轴垂直的方向）上的对齐。

`minmax(0, 1fr)` 把列的最小宽度设成 0，长内容才能收缩。卡片自己也要 `min-width: 0`，文字再靠 overflow-wrap 换行。只给父容器写 width: 100%，消除不了子元素的最小尺寸。

列轨道的数量由 CSS 决定，不随卡片数量变化。桌面是四列时，只剩一张卡片也不会横跨整行：

<Effect kind="page" preview="c15/single" />

auto-fit 和 auto-fill 会按可用空间自动生成轨道，适合另一种需求。本课用固定断点，得到确定的单、双、四列。

**Java 对照：** 用过 FlowLayout 的话，换行的思路可以借用；但这只是经验相通，CSS 属性和 Swing API 并不一一对应。

## 3. 移动优先，媒体查询逐步增加列数

移动优先指基础样式先让窄屏成立，屏幕变宽再增加列数。媒体查询（`@media`）只在条件成立时让里面的规则生效。

```css
@media (min-width: 42rem) {
  #list { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@media (min-width: 70rem) {
  #list { grid-template-columns: repeat(4, minmax(0, 1fr)); }
}
```

<Effect kind="console" title="设备模式切三种宽度，选中 #list">

```text
> getComputedStyle($0).gridTemplateColumns
360px  → '328px'
768px  → '360px 360px'
1280px → '284px 284px 284px 284px'
```

</Effect>

[设备模式](https://developer.chrome.com/docs/devtools/device-mode)是 DevTools 里模拟手机、平板宽度的工具栏，点 DevTools 左上角的「切换设备工具栏」图标打开。

rem 是相对根字号的单位，这里 1rem 是 16px，所以两个断点是 672px 和 1120px。1280px 同时满足两条查询，后写的同优先级声明胜出。媒体查询不增加选择器权重，仍按 C02 的层叠规则比较。

<Predict question="把两条媒体查询的先后顺序对调，1280px 下是几列？">

```css
@media (min-width: 70rem) {
  #list { grid-template-columns: repeat(4, minmax(0, 1fr)); }
}
@media (min-width: 42rem) {
  #list { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
```

<div slot="answer">

```text
'584px 584px'
```

两列。两条查询都成立，后写的两列声明覆盖了四列，这就是「明明写了四列，桌面还是两列」。

</div>
</Predict>

**记住：** 移动优先时，min-width 查询按从小到大的顺序写。

**Java 对照：** Swing 窗口缩放时，布局管理器按同一套规则重排；媒体查询则按视口宽度换用另一组声明。

## 4. 焦点与反馈也属于可用布局

能用键盘操作、能看到错误，布局才算可用。焦点（当前接收键盘输入的元素）要看得见，提示出现时页面不要跳动。

```css
:focus-visible { outline: 3px solid #1266bb; outline-offset: 3px; }
#feedback, #stock-error { min-height: 1.8em; }
```

<Effect kind="page" preview="c15/focus" />

`:focus-visible` 在键盘操作和文本输入框上显示外框，鼠标点按钮时一般不显示。错误区预先留出一行高度，错误出现时下面的按钮不会被推开。编辑区用 hidden 隐藏，展开后焦点移到库存输入框。

- 自定义属性（CSS 变量，如 --text）可以集中管理文字、背景和边框色，再用 prefers-color-scheme 换一套值。
- 颜色不能单独表达错误，要保留错误文字和 aria-invalid。

**记住：** 不要去掉焦点外框，要给反馈预留位置。

## 常见错误与调试

1. **现象**：在 styles.css 末尾临时加一行 `article { min-width: 600px; }`，360px 下页面可以向右拖。

<Effect kind="page" preview="c15/overflow" />

2. **工具**：Elements 选中卡片看 Computed，打开 Grid overlay（显示网格线的叠加层）。再在 Console 比较页面宽度和视口宽度：

<Effect kind="console" title="360px 下的 Console">

```text
> document.documentElement.scrollWidth
616
> innerWidth
360
```

</Effect>

3. **证据**：Computed 里卡片的 min-width 是 600px，列表本身只有 328px。页面被卡片撑宽，父容器的宽度没有错。
4. **原因**：子元素的最小尺寸挡住了列轨道收缩。
5. **修复**：删掉这一行，保留 `min-width: 0`、`minmax(0, 1fr)` 和文字换行。不要靠整页 `overflow: hidden` 把内容裁掉。
6. **确认**：三种宽度都没有横向滚动，列数为 1、2、4。按 Tab 能看到每个控件的焦点。

## 小结

- border-box 让 width 等于外框，margin 仍在外面。
- Flex 排一维的工具栏，Grid 排二维的卡片，轨道数量由 CSS 决定。
- 移动优先：基础样式管窄屏，媒体查询从小到大加列。
- 允许收缩、清楚的焦点和预留的反馈位置，共同保证窄屏可用。
