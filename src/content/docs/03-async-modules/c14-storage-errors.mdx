## 1. localStorage 保存字符串，不保存引用

新增 src/services/storage.js，先写上方卡中的 snapshot 部分。格式是 version 为 1、products 为商品数组；命名空间为 js_web:inventory:vanilla:v2，与网站学习进度分开。

**先猜一猜：** 读取并 JSON.parse 后修改对象，存储会立刻跟着变吗？

不会。内存对象与存储文本是两份值，重新编码并 setItem 才能持久化。localStorage 同步读写字符串，同源标签可见；不同源或浏览器不自动共享。限制存储或配额满时，访问和写入都可能抛错。

继续写入保存与读取部分：

<CodeExcerpt snippetId="c14-save" />

encodeSnapshot 在接触旧存储前完成 decodeSnapshot 校验。有效旧值写入 backup，损坏旧值写入 damaged，再写新值。写入抛错时调用者保留当前内存状态，不能先显示成功。

JSON.parse 只检查语法。`{"stock":"3"}` 能解析，但不符合商品契约。名称、分类、库存、整数分、标签及唯一 id 仍由共享规则检查。表单可以转换文本；导入 JSON 应拒绝错误字段类型。

**先猜一猜：** 非法新值在 encodeSnapshot 就失败，旧 JSON 会被备份或覆盖吗？

都不会，副作用尚未开始。Java 的序列化也不能代替业务字段验证。

## 常见错误与调试

1. **现象与触发**：先保存两次合法编辑以产生备份，在 Application → Local Storage 把本课键改为 `{broken`，刷新显示读取失败。
2. **工具**：查看该键与 :backup，Sources 在 decodeSnapshot 的 JSON.parse 暂停异常。
3. **证据**：当前原文不能解析，backup 仍有效，HTML 和恢复按钮仍存在。
4. **原因**：持久文本也是外部输入，刷新不会使坏 JSON 恢复。
5. **修复**：通过恢复按钮走 recoverProducts；保持 try/catch 与先校验再替换。
6. **确认**：恢复后六项可见，:damaged 保留坏原文。导入 stock 为字符串的文件应报错，原存储与商品不变。`check C14` 用隔离浏览器和内存存储检查。
