## 1. 回调描述完成后要做什么

同步函数直接返回数据；异步加载在稍后给出结果。新增 src/services/load-products.js，写入上方对照卡的 JS。import seed 使用 JSON 导入属性；delay 模拟等待，fail 用来确定地演练失败。

Promise 的 executor 立即执行；resolve/reject 只能确定一次结果，pending 之后进入 fulfilled 或 rejected。then 返回新 Promise，回调接收成功值；catch 接收拒绝原因。

## 2. 主线程、任务与微任务各在什么时候执行

Promise 回调进入微任务队列；setTimeout 回调是后续任务。同步栈清空后先运行微任务，再有机会处理下个任务。

**先猜一猜：** 在当前网页 Console 一次执行下面代码，先看到 3 还是 2？

```js
console.log(1);
setTimeout(() => console.log(4), 0);
Promise.resolve().then(() => console.log(3));
console.log(2); // 完整输出：1、2、3、4
```

输出 1、2、3、4。0 表示满足计时条件后可以排队，不能抢占同步代码。Java CompletableFuture 可以把工作交给线程池；这段 Promise 不增加线程。

![调用栈、任务队列与微任务队列的执行顺序](../../../assets/diagrams/c12-browser-event-loop.svg)

先看当前任务的同步调用，再看微任务检查点，最后看后续任务。浏览器可在任务之间渲染；持续递归排微任务或做大量同步计算都会延迟交互。

## 3. 返回内层 Promise，等待才能接成链

loadProducts 内第一层 then 必须 return 内层 Promise。then 的返回值决定下一步：普通值成为成功值，Promise 被继续等待，throw 变成拒绝。

**先猜一猜：** 去掉 `return new Promise(...)` 的 return，调用者会一直等计时器吗？

不会。回调隐式返回 undefined，外层链先成功，下一步拿到 undefined。内层计时器仍会执行，但结果已经脱离调用链。延长 delay 不能修复缺失的依赖关系。

```js
Promise.resolve(12)
  .then((stock) => stock + 3)
  .then((stock) => Promise.resolve(stock * 2))
  .then(console.log); // → 30
```

Java thenApply 对应普通映射，thenCompose 继续异步组合；JS 的 then 会吸收返回 Promise 的最终状态。

## 常见错误与调试

1. **现象与触发**：在实际 loader 中去掉内层 Promise 前的 return，刷新页面。commit 收到 undefined，不能显示六项。
2. **工具**：Sources 打开 load-products.js，在 then 回调末尾和 app.js 的 commit(loaded) 设断点。
3. **证据**：先进入 commit，loaded 是 undefined，计时器尚未完成。
4. **原因**：外层 then 没有接入内层异步任务。
5. **修复**：补回 return，末端 catch 显示错误，finally 恢复按钮。
6. **确认**：成功有 6 项，模拟失败可见且重新加载按钮可用，再加载又得到 6 项。运行 `npm run lab -- check C12`。

## 小结

- Promise 表示一次异步结果，回调遵循事件循环。
- 返回值建立依赖，throw 与拒绝沿链传播。
- catch 决定恢复还是传播，finally 共同收尾。
