**先猜一猜：** 商品名是 `<img src=x onerror=alert(1)>` 时，会出现图片还是文字？

它显示成文字。textContent 写文本节点，不把数据解析成 HTML。innerHTML 会解析标签与事件属性，不能拿它拼接导入的商品名。[DOM 操作](https://developer.mozilla.org/zh-CN/docs/Web/API/Document_Object_Model/Introduction)与 Java 控件树都是对象操作，但 HTML 解析是新的输入边界。

querySelector 返回第一个节点，找不到是 null。querySelectorAll 返回静态 NodeList：查询后新插入的节点不会自动出现在原列表中，重新查询才会看到新成员。

## 常见错误与调试

1. **现象与触发**：在 app.js 把 #list 的 click 注册移进 render，并将按钮判断临时简化为 `if (!button) return`。筛选后点击，一次补了多件。
2. **工具**：Chrome Sources → Event Listener Breakpoints → Mouse → click；在补货 commit 行设断点。
3. **证据**：一次点击多次停在同一行，Call Stack 来自不同匿名监听；Elements → Event Listeners 能看到注册项累积。
4. **原因**：每次创建的箭头函数都是新对象，addEventListener 不替你去重；省略 contains 归属检查后，重绘前的旧目标仍被后续监听处理。
5. **修复**：监听移出 render，恢复 contains 边界，只绑定到稳定的 #list；删除错误注册后整页重新加载。
6. **确认**：两次各补 1 件，P004 从 3 到 4 再到 5；筛选 P004 保存为 8，P001 仍为 12。若列表消失，Elements 右键 #list → Break on → Node removal，追踪删除祖先的调用。
