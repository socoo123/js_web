## 1. async/await 让依赖顺序回到代码顺序

用上方卡的 JS 替换整个 load-products.js。async 总是返回 Promise；return 普通值成为成功结果，throw 会拒绝。await 只暂停当前 async 函数，主线程能继续处理其他事件。

**先猜一猜：** 等待已经完成的 Promise，“读取结束”会先于“调用结束”吗？

```js
async function inspectLoad() {
  await Promise.resolve();
  console.log("读取结束");
}
inspectLoad();
console.log("调用结束"); // 先调用结束，再读取结束
```

await 后续进入微任务。Java Future.get 可阻塞调用线程；这里让出执行。try/catch 要覆盖 await；直接 return 稍后拒绝的 Promise，当前 catch 捕获不到那次拒绝，需 return await 才进入当前异常分支。

## 2. fetch 的响应分两步处理

fetch 先给 Response，读取 body 是后续异步工作。loader 先判断 response.ok，再读文本，用既有 importProducts 校验 JSON 语法、商品字段及重复 id。

统一入口把 data/products.json 原样复制为开发和构建用的静态资源；改数据仍只改 data 文件。默认 `./products.json` 相对页面 URL 解析，不相对 loader 文件解析。

| 现场 | Network / Console 证据 | 页面应该做什么 |
| --- | --- | --- |
| 404 | Status 404，Response 可能是 HTML | 显示 HTTP 404，停止解析 |
| 200 但非 JSON | Response 是错误正文 | 显示解析错误，结束加载 |
| 离线 | 请求 failed，fetch 拒绝 | 显示失败并保留重试 |
| 空数组 | Response 为 [] | 显示没有商品，属于成功空态 |

协议、主机、端口共同决定同源。跨源响应能否被脚本读取由服务器 CORS 响应头决定；no-cors 的不透明响应不能用来读 JSON。前端不能替服务器开放权限。[fetch 使用方式](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API/Using_Fetch)。

## 4. 等待一组任务：顺序由依赖决定

**先猜一猜：** 对 async 回调使用 forEach，外面 await forEach 就能等所有加载吗？

```js
const counts = [];
await [1, 2].forEach(async (value) => {
  await new Promise((resolve) => setTimeout(resolve, 0));
  counts.push(value);
});
console.log(counts.length); // → 0
```

forEach 返回 undefined，不收集回调 Promise。互不依赖的任务先 map 为 Promise 数组，再 await Promise.all；依赖前项结果则用 for...of 中逐次 await。

```js
const counts = await Promise.all([1, 2].map(async (value) => {
  await Promise.resolve();
  return value;
}));
console.log(counts.length); // → 2
```

Promise.all 任一拒绝就拒绝，不自动取消其他任务；保留每项成败用 allSettled。并发是等待重叠，不等于同时执行多段 JS 同步循环。

## 常见错误与调试

1. **现象与触发**：删除实际 loader 中 response.ok 判断，点击模拟失败，出现 JSON 解析错误。
2. **工具**：Network 选 missing.json，查看 Headers → Status Code 和 Response；Sources 在读取 body 后设断点。
3. **证据**：HTTP 404 已得到 Response，正文不是商品 JSON，response.ok 为 false。
4. **原因**：fetch 不因普通 HTTP 错误自动拒绝，解析失败只是下游症状。
5. **修复**：恢复解析前的状态判断，调用者区分 AbortError。
6. **确认**：404 显示 HTTP 404；离线失败后可重试；正常与 [] 分别显示六项和空态。`npm run lab -- check C13` 检查实际 loader。

## 小结

- await 表达当前函数的依赖，不阻塞线程。
- HTTP 状态、格式、业务结构是三层检查。
- Promise.all 收集并发结果，AbortController 显式取消。
