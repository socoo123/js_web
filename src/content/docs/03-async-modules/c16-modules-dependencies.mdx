## 1. 具名导出与默认导出是不同接口

ESM 用 export/import 建立显式依赖，模块各有作用域并按严格模式执行。本项目 package.json 已有 type:module，网页入口已有 type=module。

```js
// validation.js：具名导出
export function parseStock(text) { /* 搬入已有函数体 */ }
// 其他模块：名称必须匹配，并写 .js 扩展名
import { parseStock } from "./validation.js";
```

这段展示接口位置，函数体保留你原有的实现。default export 用不带花括号的导入，可在本地另起名字；具名导入的别名使用 as。浏览器按 URL 找文件，不会自动尝试补 .js；裸包名需构建工具或 import map 解析。

## 3. 活绑定、初始化与动态加载

**先猜一猜：** 模块导出 let count，函数把它加一，导入者稍后读 count 能看到新值吗？

能。ESM 导入是只读活绑定，导入者不能重新赋值，导出模块更新后仍能读到新值。同一模块 URL 的正常导入只初始化一次。普通 `const before = count` 则保存当时值。

```js
// counter.js
export let count = 0;
export function next() { count++; }
```

```js
// caller.js，页内预测
import { count, next } from "./counter.js";
const before = count;
next();
console.log(before, count); // → 0 1
```

循环引用时在依赖初始化前读取 let/const 可能触发暂时性死区。优先调整依赖方向，而不是四处延迟执行掩盖问题。动态 import() 在执行到时返回 Promise，适合按需加载；它不意味着每次创建独立模块。

Node 还支持 CommonJS 的 require/module.exports；其解析与导出模型不同。`.cjs` 明确 CommonJS，`.mjs` 明确 ESM；本工作区统一使用 ESM。

## 4. 标准年份、提案阶段与环境支持分别查

**先猜一猜：** 某特性到了 Stage 4，所有浏览器就都能运行吗？

不是。Stage 4 表示标准流程完成，年度版本与部署环境支持还要分别确认。课程主线使用已发布的语法；未完成提案不进入必做代码。

| 特性 | 标准归属 | 当前工作区 Node 24 |
| --- | --- | --- |
| Array.prototype.toSorted | ES2023 正式标准 | typeof [].toSorted 为 function |
| Promise.withResolvers | ES2024 正式标准 | typeof Promise.withResolvers 为 function |

在 `npm run lab -- console` 输入两条 typeof 核对当前运行时。浏览器目标还应查官方兼容资料；构建工具可转部分语法，却不会自动补齐所有运行时 API。

## 常见错误与调试

1. **现象与触发**：在当前 stock.js 把具名 parseStock 导入改为默认导入，页面出现模块没有 default 导出的错误。
2. **工具**：Console 看第一条模块错误，Network 确认 validation.js 实际 200；Sources 查看导出语句。
3. **证据**：文件已下载，但只导出了名为 parseStock 的函数，没有 default。
4. **原因**：接口匹配错误与资源 404 是不同故障。
5. **修复**：恢复花括号具名导入与完整 .js 路径，保持单向依赖。
6. **确认**：check C16 的原有规则全通过，网页仍为 6/52/2634800，编辑与存储仍正常。
