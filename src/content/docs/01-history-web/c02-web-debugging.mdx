HTML 标记内容的含义和层级。Java 拼出的文本可以交给浏览器，但浏览器要按 HTML 的规则建立节点，再布局和绘制。

- `doctype` 让浏览器使用标准模式；`html lang="zh-CN"` 标明语言。
- `head` 放编码、标签页标题、移动视口和资源声明；`body` 放页面内容。
- `main` 是页面主体，`article` 是独立商品卡片，h1/h2 建立标题层级。

标签用来表达结构，CSS 决定样子。h1 与 div 不是“字体不同的两种写法”；它们给阅读顺序、键盘与辅助技术的信息不同。Java 的字符串本身没有这些页面语义。

浏览器先让块级内容按正常流排列，再应用 Flex 等布局规则。这里的 form 用 flex 把控件放到一行，wrap 允许窄屏换行；响应式课会集中练它们。

每个元素都有内容、padding、border、margin 四层。**先猜一猜：** 输入宽度写 7rem，再加 padding 和边框，边框盒子的宽度会变大吗？

本页的 `box-sizing: border-box` 把 padding 和 border 算在声明宽度内，所以边框盒子仍是 7rem；margin 在盒子外另算。默认 content-box 则把声明宽度只用于内容。rem 相对于根元素字号，百分比要结合父容器理解。

在 Elements 选中输入，右侧 Styles 看命中的规则，Computed 看最终 width 与盒模型。本页的 input 先设置 12rem，但 #amount 的 id 选择器优先级更高，所以最终是 7rem。一般先比较 id、class/属性、元素选择器的优先级；同级再看后出现的声明。继承则决定没有直接声明时能从父节点取得哪些值。

Java 的布局管理器经验能帮助你考虑容器与子元素，但 CSS 是浏览器对整棵元素树共同求出的布局结果。

## 4. URL 与加载：路径决定浏览器请求谁

本地服务地址由协议、主机、端口和路径组成。例如 `http://127.0.0.1:8060/` 使用 HTTP，请求这台机器 8060 端口的根页面。

`./app.js` 相对当前 HTML 的目录解析；`/app.js` 从域名根目录解析。目录名、文件名和大小写都要一致。GitHub Pages 使用子路径，到了交付阶段会再检查这些差异。

![页面加载：浏览器取得 HTML，建立 DOM，加载 CSS 和模块脚本；脚本查找节点并绑定事件，用户提交后再更新页面。](../../../assets/diagrams/c02-page-flow.svg)

沿请求与解析读到事件更新：HTML 负责结构，CSS 负责布局，脚本负责把数据与节点连起来。这里的 module 脚本在文档解析后执行，因此能找到前面写出的节点；模块规则在后面的专门课程展开。

在 Network 按类型查看 Doc、CSS、JS 请求。HTTP 200 表示这个响应成功；Console 的语法/运行错误则要继续看具体文件和行号。Java 的文件路径经验仍有用，但浏览器还要通过 URL 发请求，并按响应类型处理资源。

## 常见错误与调试

### 卡片还在，按钮却没有响应

**现象**：把 HTML 的 `src="./app.js"` 改成 `src="./ap.js"` 后刷新，卡片和按钮仍在，按按钮没有 JS 反馈。

**工具**：F12 → Network，勾 Disable cache，重新加载，过滤 JS。再看 Console 的第一个加载错误。

**证据**：ap.js 请求返回 404；编辑器中真正存在的文件叫 app.js。卡片的静态结构来自 HTML，所以它仍能出现。

**原因**：脚本路径拼错，事件监听代码没有执行。

**修复**：恢复 `./app.js`。文件名保持相同大小写，继续使用同一工作区与同一服务。

**确认**：刷新后 app.js 返回 200，价值显示 478800 分；Sources 的处理函数断点可以命中。窄屏还应检查 Computed，避免固定宽度把整页撑开。

## 小结

- HTML 建立有含义的节点，CSS 决定布局与外观。
- DOM 更新要明确写回节点；数据赋值不会自动改页面。
- label、form、焦点轮廓让键盘操作有基础。
- 资源路径错误先看 Network，运行错误再看 Console 与 Sources。

自测：为什么变量变了节点没变？为什么脚本 404 后卡片仍能出现？label 的 for 指向哪里？border-box 怎样计算宽度？
