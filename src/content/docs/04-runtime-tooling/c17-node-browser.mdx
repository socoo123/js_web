## 1. 同一门语言，不同宿主能力

新增 src/cli/report.js，写入上方对照卡的完整 JS。浏览器与 Node 都能执行共享规则；document 属于浏览器，fs 属于 Node，不能把报表模块导入网页。

**先猜一猜：** 在工作区 `npm run lab -- console` 中，下面三个 typeof 是什么？

```js
console.log(typeof document); // → undefined
console.log(typeof process);  // → object
console.log(typeof fetch);    // → function
```

Node 使用 V8 执行 JS，提供进程、文件和网络能力；I/O 可由系统或线程池处理，完成后再调度 JS 回调。await 不会为业务函数开线程，重计算仍可阻塞当前 JS 执行。Java JVM 也需要标准库与操作系统配合，不能把引擎和宿主能力混为一谈。

<a id="2-文件读取先确定路径的基准"></a>

## 2. 路径先确定基准，再读取文件

report 的 new URL 相对 import.meta.url 定位。readFile 返回 Promise，指定 utf8 得到字符串，否则得到 Buffer；解析后 summarize 同时执行业务校验。

在工作区运行 `npm run lab -- report`，输出商品数 6、总库存 52、总价值 2634800 分。再退到工作区父目录，运行 `node inventory/src/cli/report.js`；若你的工作目录名称不同，替换 inventory。输出相同。

**先猜一猜：** `readFile("data/products.json")` 从哪个目录开始找？

从 process.cwd()，即启动进程的目录，不是源文件目录。读用户指定文件时 cwd 可以是正确基准；读取模块自带资源时应使用模块 URL。URL 与操作系统路径互转可用 node:url 的 fileURLToPath/pathToFileURL，不手工删除 file: 前缀。

<a id="3-命令行参数和环境变量都是输入"></a>

## 3. 参数、环境变量与退出状态都是接口

process.argv 前两项是可执行程序和入口，后面才是用户参数。process.env 的值通常是字符串或 undefined，需要转换并校验。

```js
const text = process.env.LOW_STOCK_LIMIT ?? "5";
const limit = Number(text);
if (!Number.isInteger(limit) || limit < 0) throw new Error("阈值需要非负整数");
console.log(limit); // 未设置变量时 → 5
```

错误时可设置 process.exitCode=1，让调用脚本知道失败。异步写文件要 await 成功后再报完成；try/catch 需覆盖 await。不要提前 process.exit(0) 截断尚未完成的输出或 I/O。

<a id="4-buffer-与-stream字节和分块"></a>

## 4. Buffer、stream 与 inspect 各解决什么

Buffer 表示字节，字符串长度与 UTF-8 字节数可能不同；stream 分块处理，适合大文件，pipe/pipeline 处理背压与错误。当前六商品文件很小，用 readFile 更直接。

```js
const bytes = Buffer.from("库", "utf8");
console.log(bytes.length); // → 3
console.log(bytes.toString("utf8")); // → 库
```

在工作区运行 `node --inspect-brk=127.0.0.1:9229 src/cli/report.js`，Chrome 打开 chrome://inspect → Open dedicated DevTools for Node。在 readFile 与 summarize 行设断点，继续执行后看 products 与 summary；这次调试的是 Node 进程，不是网页 Console。完成后结束该进程。

Java 调试器也能附着进程，Node inspect 让调试器查看该进程的 JS 栈和作用域。

## 常见错误与调试

1. **现象与触发**：在实际 report.js 把文件 URL 改为相对字符串 data/products.json，从父目录运行，得到 ENOENT。
2. **工具**：用 inspect 在 readFile 行暂停，Watch 添加 process.cwd()、import.meta.url 和 file。
3. **证据**：cwd 是父目录，模块 URL 仍指向 src/cli/report.js；相对字符串缺少稳定文件基准。
4. **原因**：把启动目录当成模块目录。
5. **修复**：恢复 new URL 与 import.meta.url，保持浏览器模块不依赖 fs。
6. **确认**：两个 cwd 得到相同报表，check C17 会从不同目录调用当前 report.js；故意改 summarize 后它也应反映当前代码。

## 小结

- JavaScript 规则可共享，宿主 API 需隔离。
- cwd 与模块 URL 是不同基准。
- Buffer 处理字节，stream 处理分块，退出状态告诉调用者结果。
