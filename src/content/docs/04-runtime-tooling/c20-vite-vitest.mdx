## 5. TypeScript 短桥接：类型会被擦除

在工作区执行 `npm run lab -- experiment types`。工具只在 .lab/sandboxes 内写一份 price.ts：

```ts
const stock: number = "3";
console.log(stock + 1);
```

Vite 转译这段仍能生成 JS，运行输出 31；独立 tsc 类型检查报 string 不能赋给 number。照终端打印的命令，在隔离文件把字符串改为数字后再检查，应通过，运行结果为 4。

类型标注、接口、泛型帮助编辑与静态分析，运行时不保留这些约束。即使 `JSON.parse(text)` 被断言为 Product，真实输入仍可能缺字段；共享校验继续必需。[Vite 的 TypeScript 职责](https://vite.dev/guide/features.html#typescript)。

## 常见错误与调试

1. **现象与触发**：在实际 validation.js 删除 parseStock 的判空分支，保留 Number 转换，运行 npm test。
2. **工具**：Vitest 失败报告，定位“拒绝非法库存”用例及输入空白。
3. **证据**：期望抛错，实际没有抛错；Number(空白) 为 0。构建仍可通过。
4. **原因**：语法有效不代表业务边界正确，单测之前漏选了输入分区。
5. **修复**：恢复判空，保留空白/合法零/非法/越界回归，不删除断言。
6. **确认**：原用例先红后绿，check C20、build 和生产页面都通过。再完成 TS 实验，分别确认转译与类型检查结果。
