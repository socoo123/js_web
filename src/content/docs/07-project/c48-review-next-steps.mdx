## 1. 从历史到生态：先说清代码在哪里运行

<a id="1-从历史到生态先说清代码在哪里运行"></a>

JavaScript从浏览器脚本发展为年度ECMAScript标准，也进入Node、Bun等宿主。把技术放回负责的层，才能解释“同一份代码为什么这里能跑、那里不能跑”。

| 层次 | 本项目中的例子 | 负责什么 |
| --- | --- | --- |
| 语言与内建结构 | 函数、Promise、Array/Map/Set | 值与执行规则 |
| 引擎与宿主 | V8；浏览器、Node、Bun | 执行语言；提供DOM、文件或I/O |
| 工程工具 | npm/Yarn/pnpm、Vite、Vitest | 安装依赖、构建与测试 |
| UI与业务 | HTML/CSS、React、四个adapter | 把库存规则变成可操作界面 |

Node和Bun是运行时；Bun还集成包管理等工具。npm、Yarn、pnpm主要管包与工程任务，不能和语言、数据结构混为一类。Java也会区分JVM、构建工具和业务库。

SAPUI5、OpenUI5、UI5 Web Components与React包装库分别保留在[UI5家族速查](/js_web/reference/ui5-family/)。本次现场增量回到React主应用，不把四种界面再全部实现一遍。

## 2. Java经验继续用，值与身份重新判断

<a id="2-java-经验继续用值与身份重新判断"></a>

现场需求只增加一个已学过的条件：**低库存为1–5件，售罄0不算**。不新增框架、不增加第二份商品state，也不改公共业务数据。

具体约定：

- 在App的Toolbar内加原生checkbox，label为“仅低库存”；选中写入hash查询参数 `stock=low`，取消删除该参数。
- 在InventoryView里，从searchParams派生条件；接在现有名称/分类筛选之后、排序之前，与它们取交集。未知stock值按未选中处理。
- 可见摘要仍由visible计算。初始选中只显示P004/P006，8件、539200分；清除后恢复六种、52件、2634800分。
- 条件随hash刷新恢复；筛选不能调用repository保存。低库存内把P004保存为8，它应离开结果，焦点回标题；清除筛选看到它仍是8、全量57，P001仍12。

**先猜一猜：** 新数组能保证修改后旧商品不变吗？

```js
const oldItems = [{ id: "P002", stock: 0 }];
const newItems = [...oldItems];
console.log(oldItems === newItems); // → false
console.log(oldItems[0] === newItems[0]); // → true
```

容器换身份，内部对象仍共享。过滤和排序应派生视图，库存写入则保持已有不可变更新链。Java复制集合与复制内部对象也是两个动作。

**先猜一猜：** await暂停了调用方的所有代码吗？在Node或Console执行：

```js
async function reviewOrder() { console.log("开始"); await Promise.resolve(); console.log("继续"); }
const reviewing = reviewOrder();
console.log("调用方");
await reviewing;
// → 开始、调用方、继续
```

await只暂停当前async函数，调用方仍往下走。本例没有新工作线程；Java的Future经验不能直接当作JS的线程模型。

## 4. 阅读新版本：把标准状态与环境支持分开

<a id="4-阅读新版本把标准状态与环境支持分开"></a>

看到新特性先问它解决什么问题，再分别查“正式标准/提案阶段”“目标环境支持”“项目如何采用”。例如toSorted解决复制排序，但对象元素仍共享引用：

```js
const reviewedStocks = [12, 0, 7];
console.log(reviewedStocks.toSorted((a, b) => a - b)); // → [0, 7, 12]
console.log(reviewedStocks); // → [12, 0, 7]
```

toSorted已进入正式标准；支持范围仍看[MDN兼容表](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/toSorted)。旧环境可复制后sort，转译处理语法，polyfill补运行时API，两者不同。Java升级也会核对运行环境，前端还要考虑用户浏览器。

Stage4是完成的提案，具体进入哪一年度再看正式收录；更早阶段仍会改变。React看官方版本与迁移说明，Node看维护阶段；不要仅凭“包安装成功”决定升级。保留清单、锁、可恢复提交和风险回归。

## 常见错误与调试

<a id="数组换了旧库存却跟着变了"></a>

**现象**：P002补成1，旧库存也成了1。在 `src/core/stock.js` 的updateStock里保留现有校验，把最后的return暂时换成：

```js
// 有问题的写法：只复制数组，修改的商品仍共享
const next = [...products];
next.find((product) => product.id === id).stock = stock;
return next;
```

**工具**：Sources在赋值行设断点，或运行本课的浅复制测试。**证据**：数组不同，P002对象相同；旧值由0变1。**原因**：展开只复制引用，没有复制目标记录。

**修复**：恢复这行，只复制被修改的路径：

```js
return products.map((product) => product.id === id ? { ...product, stock } : product);
```

**确认**：新P002=1，旧P002=0；新数组和目标对象不同，未改P001仍共享。新库存正确只是一个条件，必须同时保护旧快照。Java里的浅集合复制也要注意内部可变对象。
