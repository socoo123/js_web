## Java 程序员先看这里

你熟悉“校验 → 调用异步服务 → 成功或失败 → finally 收尾”。React 的 Action 把这段过程与等待界面联系起来。它不是 Java 注解事务，也不会把函数搬到服务器。`useReducer` 的 reducer 必须纯；`useActionState` 的操作函数允许异步与副作用。

## 1. 操作结果的第一个参数，不是表单

<a id="useactionstate-多传一个上次结果"></a>

**`useActionState` 调用的操作函数先收上次结果，再收本次数据。** 普通 `<form action={save}>` 则把 FormData 作为第一个参数。两种签名不要混用。[官方参数说明](https://react.dev/reference/react/useActionState)明确区分了它们。

打开 `src/react/ProductEditor.jsx`，删除旧的 `submit(event)`、独立的 errors state 与旧 return。把整个文件依次替换为本节、下一节和第三节的代码。第一段打开组件函数，后两节继续写在这个函数里。

```jsx
import React, { useState, useRef, useEffect, useActionState, useOptimistic } from "react";
import { categories, toDraft, parseDraft } from "../core/inventory.js";
export default function ProductEditor({ product, onSave, onCancel }) {
  const [draft, setDraft] = useState(() => toDraft(product));
  const fields = useRef({});
  const submitting = useRef(false);
  const [previewStock, preview] = useOptimistic(product.stock);
  const [result, submitAction, pending] = useActionState(saveAction, { errors: {}, message: "" });
  const errors = result.errors;
  function change(field, value) { setDraft((previous) => ({ ...previous, [field]: value })); }
  useEffect(() => {
    const firstError = ["name", "stock", "price", "category"].find((field) => errors[field]);
    if (!pending) fields.current[firstError]?.focus();
  }, [pending, errors]);
```

页面暂时还不能编译，补完后两节再保存。三个返回值分别是操作结果、交给 form 的入口和等待标记。`errors` 从本次结果读取，商品仍来自 prop，草稿仍属于编辑器。

<a id="练习-1上次结果是谁"></a>

**先猜一猜：** 初始结果是 `{ errors: {}, message: "" }`，第一次提交时 `saveAction` 的第一个参数是什么？答案是这份初始结果；第二个才是 FormData。下一次提交，第一个参数换成上一次的返回值。

Java 方法的参数按位置传递也是如此；这里多出的“前一次结果”由 React 保存和传回。

## 2. 草稿、等待和失败各有归属

继续在组件函数里加入操作和提交守卫：

```jsx
  async function saveAction(previousState, formData) {
    try {
      if (formData.get("productId") !== product.id) throw new Error("商品编号不匹配，请重新打开编辑器");
      const parsed = parseDraft(draft);
      if (parsed.hasErrors) {
        return { errors: parsed.errors, message: "" };
      }
      preview(parsed.value.stock);
      await onSave(parsed.value);
      return { errors: {}, message: "保存完成" };
    } catch (error) {
      return { errors: { form: `保存失败：${error.message}` }, message: "" };
    } finally { submitting.current = false; }
  }
  function guardSubmit(event) {
    if (submitting.current || pending) event.preventDefault();
    else submitting.current = true;
  }
```

结果：非法库存直接返回字段错误；合法输入先显示预计库存，再等待 `onSave`。失败被转换成可显示的结果，不会关闭编辑器。

`draft` 是受控字段的唯一草稿，直接交给已有的 `parseDraft`，不再维护另一份业务校验。FormData 中的隐藏编号用于检查提交身份；原始输入的名称、库存、价格仍由受控 state 管理，标签保留在草稿里。

<a id="请求还没结束按钮一直显示空闲"></a>

pending 提供可见等待状态，ref 在同一次同步提交入口挡住重复事件。这里禁用整个编辑区，用户不能在保存过程中修改这一笔提交。服务器项目还需要服务端幂等与并发校验；浏览器禁用按钮只解决界面入口。

**先猜一猜：** 保存失败后，草稿是 8，`product.stock` 仍为 3，预览最后显示哪个？答案是 3。`useOptimistic` 只在 Action 等待期间覆盖来源值；Action 结束后重新读取 `product.stock`，草稿则继续保留 8。

Java 的 `finally` 能收尾任务，但不会替你安排界面重新渲染；这里的等待和结果由 Hook 联系到渲染。

## 3. 连接表单与同一条 repository 写入路径

最后接上 return。下面两段连续放在同一位置，第二段包含组件的结束花括号；中间不要插入自己的结束标签：

```jsx
  return <form aria-label="商品编辑" noValidate action={submitAction} onSubmit={guardSubmit} aria-busy={pending}
    onReset={(event) => event.preventDefault()}>
    <h2>编辑 {product.id}</h2>
    <input type="hidden" name="productId" value={product.id} />
    <fieldset disabled={pending}>
      <legend>商品资料</legend>
      {[["name", "名称"], ["stock", "库存"], ["price", "价格（元）"]].map(([field, label]) =>
        <div key={field}><label htmlFor={`edit-${field}`}>{label}</label>
          <input ref={(node) => { fields.current[field] = node; }} autoFocus={field === "name"}
            inputMode={field === "stock" ? "numeric" : field === "price" ? "decimal" : "text"}
            id={`edit-${field}`} name={field} value={draft[field]} onChange={(event) => change(field, event.target.value)}
            aria-invalid={Boolean(errors[field])} aria-describedby={`error-${field}`} />
          {errors[field] && <p id={`error-${field}`} role="alert">{errors[field]}</p>}
        </div>)}
```

继续接上分类、按钮与提示：

```jsx
      <label>编辑分类 <select ref={(node) => { fields.current.category = node; }} aria-label="编辑分类" name="category" value={draft.category} onChange={(event) => change("category", event.target.value)}
        aria-invalid={Boolean(errors.category)} aria-describedby="error-category">
        {categories.map((name) => <option key={name}>{name}</option>)}
      </select></label>
      {errors.category && <p id="error-category" role="alert">{errors.category}</p>}
      <button type="submit">{pending ? "正在保存…" : "保存"}</button>
      <button type="button" onClick={() => onCancel()}>取消</button>
    </fieldset>
    <p role="status">预览库存 {previewStock} 件{pending ? "（等待确认）" : "（已保存）"}</p>
    {errors.form && <p role="alert">{errors.form}</p>}
    {!pending && result.message && <p role="status">{result.message}</p>}
  </form>;
}
```

结果：保存时按钮显示“正在保存…”，成功前不能再次点击。失败显示错误，输入值和分类留下。这里的字段全部受控，所以阻止原生 reset；需要真正重置时，按商品 key 重建编辑器或显式更新 draft。`noValidate` 保留既有的业务校验入口，错误按“名称→库存→价格→分类”聚焦；校验对象的插入顺序不是界面的字段顺序。聚焦放在 pending 结束后的 Effect，避免正在 disabled 的字段拿不到焦点。

在 `App.jsx` 的 `InventoryView` 中，找到原来 trigger 声明、openEditor 与 closeEditor 这小段，保留下面的焦点边界。`useRef` 已在本文件导入：

```jsx
  const trigger = useRef(null);
  const heading = useRef(null);
  function openEditor(id, button) { trigger.current = button; setSelectedId(id); }
  function closeEditor(target = trigger.current) {
    setSelectedId(null);
    (target?.isConnected ? target : heading.current)?.focus();
  }
```

主 return 的标题保留为 `<h1 ref={heading} tabIndex={-1}>React 库存工作台</h1>`。打开按钮被筛选移除时，关闭回到标题；这个 fallback 不参与普通 Tab 顺序。

在 `App.jsx` 的 `InventoryView` 中，加入 `failSave` state，用下面函数完整替换旧 `saveProduct`。删掉旧函数外层的 try/catch：保存失败要继续拒绝，让编辑器的 Action 接住；补货、删除的错误处理保持原样。

```jsx
  const [failSave, setFailSave] = useState(false);
  async function saveProduct(value) {
    const staysVisible = selectedId === "new"
      || selectProducts([value], { query, category }).length > 0;
    const target = staysVisible ? trigger.current : heading.current;
    await dispatch({ type: selectedId === "new" ? "created" : "saved", product: value,
      options: { fail: failSave, delay: 300 } });
    setOperationMessage(""); closeEditor(target);
  }
```

在原有条件渲染的 `<ProductEditor ... />` 前插入开关，并把该编辑器调用替换成第二行。取消用无参数回调，不把点击事件当作 DOM 焦点目标：

```jsx
    <label><input type="checkbox" checked={failSave} onChange={(event) => setFailSave(event.target.checked)} />模拟保存失败</label>
    {selected && <ProductEditor key={selectedId} product={selected} onSave={saveProduct} onCancel={() => closeEditor()} />}
```

结果：失败由 C32 的 repository 在写入前拒绝，界面显示“模拟 save 失败”；成功分支等待 repository 写入和相关 Query 刷新后才关闭。保存改名即将使该行不再匹配筛选时，提前选择标题作为焦点目标，不等原按钮卸载才发现焦点丢失。`delay` 只让等待界面容易观察。它是浏览器内 mock，没有保存 POST，也没有服务器事务；Network 中没有写请求是本项目的正常现象。

<a id="与-query-的分工"></a>

Action 管提交过程，repository 管商品与持久化，Query 管缓存，`useOptimistic` 只管编辑器内的临时预览。列表和汇总在保存成功后一起读取 Query，不能顺手再 `setProducts` 一份。

| 入口 | 适用场景 |
| --- | --- |
| [useFormStatus](https://react.dev/reference/react-dom/hooks/useFormStatus) | 通用提交按钮从**上层** form 读取 pending；不在返回该 form 的同一组件里读它 |
| [ref prop](https://react.dev/blog/2024/12/05/react-19#ref-as-a-prop) | 函数组件接收 ref 并传给 DOM；本课沿用已有 DOM ref |
| [use](https://react.dev/reference/react/use) | 读取缓存提供的稳定 Promise 或 Context；不在 render 中每次新建 fetch Promise |
| [Server Functions](https://react.dev/reference/rsc/server-functions) / RSC | 需要相应框架与执行环境；Pages 的客户端编辑器没有这条服务端调用链 |

<a id="react-19-更新索引"></a>

把异步函数命名为 Action 不会自动进入 Transition。本课由 form 的 action prop 建立上下文；若以后用普通按钮手动调用生成的 submitAction，要用 `startTransition(() => submitAction(payload))`。React 版本与 API 状态以[官方版本入口](https://react.dev/versions)为准，不按更新列表给当前项目堆功能。

## 小结

- `useActionState` 的 FormData 是第二个参数。
- 等待与结果属于 Action；草稿属于编辑器；正式商品属于 repository。
- 乐观显示不是持久化，失败后回到来源值。
- 成功后才关闭编辑器，保存与 Query 刷新需要真正 await。
