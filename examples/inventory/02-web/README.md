# 库存项目 · 阶段 2：原生页面

当前参考状态：C13 完成。接续 C11 的筛选和库存编辑，改为通过 HTTP 加载固定 JSON，加入加载、空数据、失败和重试。

## 运行

在仓库根目录运行 `python3 -m http.server 8000 --bind 127.0.0.1`，打开 `http://127.0.0.1:8000/examples/inventory/02-web/`。无需安装依赖。

| 文件 | 作用 |
| --- | --- |
| index.html | 搜索、分类、商品列表、库存表单、状态提示和失败重试 |
| products.json | 与 `../../shared/products.json` 一致的固定数据 |
| app.js | fetch、HTTP/JSON/数组检查、加载状态、筛选、委托、库存校验、渲染和焦点恢复 |
| style.css | 沿用 C11 的基础排版、错误信息与可见焦点 |

使用一个 defer 经典脚本；C16 再拆成 ES 模块并复用阶段 1 的 Inventory。加载状态为 loading、ready、error；ready 时再按数组和筛选结果区分两类空态。

首次打开读取相对路径 `./products.json`，失败后可重试；成功后的筛选只处理内存数据，保留编辑。新响应经 JSON 解析产生独立对象，只编辑 stock，接受 0–99999 整数；刷新后重新读取固定起始数据。

## 验收

- 正常：6 种、52 件、总价值 2634800 分（26348.00 元）。
- 慢网且禁用缓存：先显示加载提示，列表为空，搜索/分类/重试禁用，结束后恢复；列表 aria-busy 从 true 变 false。
- 分类配件有 P004、P005，再搜键盘为空态；汇总始终统计全部商品。
- 恢复全部，搜索 p002，编辑 0 为 3：55 件、26735.00 元；再筛选不会重新请求或覆盖编辑。
- 空值、-1、3.8、100000 无法保存；0 与 99999 可保存；保存和取消恢复焦点。
- 暂时改名 products.json，刷新产生 404：显示失败和重试，Console 保留详细错误；恢复文件名，点重试恢复原始数据。
- 失败后输入筛选词，错误提示保留；重试成功后应用当前筛选条件。
- 临时将 JSON 改成 `[]`：暂无商品、汇总 0、不显示重试；语法错误或 `{ "products": [] }` 则进入失败分支。实验后恢复固定文件。
